## 0. 지난 라운드의 결과

**좌클릭 문제는 해결됐습니다.** 원인은 포그라운드 권한이 아니라 `NIF_MESSAGE` 확인 없이 콜백 번호를 덮어쓰던 것이었습니다. 로그의 `asfw=1`이 86회 전부이므로 권한 가설은 폐기합니다.

일곱 항목 가운데 다섯이 좌클릭·더블클릭·우클릭 모두 동작합니다. 남은 것은 셋입니다.

| 남은 문제 | 이번에 할 일 |
|---|---|
| 볼륨·배터리가 클릭에 반응하지 않는다 | 고치지 않습니다. 사용자가 **숨길 수 있게** 합니다 |
| 카카오톡 모서리에 어두운 픽셀이 남는다 | 이중 프리멀티플라이를 검증하고 고칩니다 |
| explorer 아이콘의 활성화 한계가 기록되지 않았다 | 문서에 적습니다 |

## 1. 개별 아이콘을 숨기고 되살릴 수 있어야 한다

### 1-1. 왜 필요한가

볼륨과 배터리는 explorer가 `Shell_NotifyIcon`으로 등록하되 **클릭은 XAML 트리에서 직접 처리하는** 아이콘입니다. 레거시 콜백은 그림과 툴팁을 넘기는 통로일 뿐 활성화 경로가 아니므로, 우리가 무엇을 보내도 반응이 없습니다. 볼륨은 콜백 번호조차 오지 않아 `reason=no_callback`으로 버려지고, 배터리는 `posted=1`인데 explorer가 무시합니다.

**우회할 수 있는 결함이 아니라 방식의 경계입니다.** 사용자와 상의해서 이 둘을 상단바에서 빼기로 정했습니다. 볼륨은 나중에 bamti 자체 위젯으로 만듭니다. 배터리와 네트워크 위젯은 이미 있습니다.

**블루투스는 남깁니다.** 같은 explorer 아이콘이지만 클릭이 정상 동작합니다. 그러므로 "explorer 소유"를 기준으로 한꺼번에 거르면 안 됩니다. `tray_system_icons` 설정을 쓰는 방법도 같은 이유로 쓸 수 없습니다.

### 1-2. 지금 왜 못 하는가

숨기는 기능 자체는 있습니다. `WidgetSettings::tray_hidden_keys`와 `MenuBar::ShowTrayIconMenu`의 `이 아이콘 숨기기`(`kTrayHideIconCmd`)입니다.

**그런데 가로채기 모드에서는 그 메뉴에 닿을 수 없습니다.** `menu_bar.cpp` 454행이 이렇게 되어 있습니다.

```cpp
if (hit->id.rfind("bamti.tray/", 0) == 0) {
  if (tray_.ForwardsContextMenu()) {
    // 우클릭을 앱으로 전달하고 끝낸다
    return 0;
  }
  ShowTrayIconMenu(screen, hit->id);   // ← 가로채기에서는 도달하지 않는다
}
```

가로채기 백엔드는 `ForwardsContextMenu()`가 `true`이므로 우클릭이 항상 앱으로 갑니다. bamti 자신의 메뉴가 뜰 자리가 없습니다.

**되살리는 방법은 아예 없습니다.** 한 번 `tray_hidden_keys`에 들어가면 `settings.json`을 직접 편집하는 수밖에 없습니다. 이것도 함께 고칩니다.

### 1-3. 어떻게 고치는가

**상단바 우클릭 메뉴에 하위 메뉴를 하나 더하십시오.** 이름은 `트레이 아이콘`입니다.

`ShowContextMenu`에서 `트레이 아이콘 가로채기(실험)` 항목 아래에 넣습니다. 하위 메뉴는 다음을 담습니다.

- 지금 미러 중인 항목과 숨긴 항목을 **모두** 한 줄씩 나열합니다.
- 각 줄의 문구는 툴팁입니다. 툴팁이 비어 있으면 `(이름 없음)`으로 적습니다. 길면 40자에서 자릅니다.
- 숨기지 않은 항목에는 `MF_CHECKED`를 붙입니다. 즉 체크가 곧 "표시 중"입니다.
- 항목을 고르면 그 키의 숨김 상태가 뒤집힙니다. 숨겨져 있으면 `tray_hidden_keys`에서 빼고, 아니면 넣습니다.
- 하나도 없으면 `MF_GRAYED`로 `미러 중인 아이콘이 없습니다` 한 줄만 둡니다.

명령 id는 기존 상수와 겹치지 않는 범위를 한 덩어리로 잡으십시오. 예를 들어 `kTrayItemCmdBase = 4000`부터 항목 순서대로 더해 쓰고, 상한을 `kTrayHiddenKeysMax`와 같은 64개로 두십시오. 그보다 많으면 뒤쪽은 나열하지 않고 마지막 줄에 `MF_GRAYED`로 `이하 생략`을 적습니다.

메뉴를 만들 때의 순서와 키를 멤버에 보관해 두었다가 명령 처리에서 그 인덱스로 키를 찾으십시오. 문자열 id를 다시 파싱하지 마십시오.

**숨긴 항목의 툴팁은 어디서 얻는가.** 숨긴 항목은 상태 목록에서 빠지므로 툴팁을 알 수 없습니다. 마지막으로 본 툴팁을 키와 함께 기억해 두었다가 쓰십시오. 프로세스를 새로 띄운 직후처럼 기억이 없으면 `(숨김)`과 키 앞 6자리를 적어 사용자가 구분할 수 있게 하십시오.

### 1-4. 기존 경로는 그대로 두십시오

`ShowTrayIconMenu`와 `kTrayHideIconCmd`는 UIA 백엔드에서 여전히 쓰이므로 지우지 마십시오. 이번에 더하는 하위 메뉴는 두 백엔드 모두에서 동작해야 합니다.

### 1-5. 키가 안정적이지 않은 경우를 문서에 적으십시오

가로채기 항목의 키는 GUID가 있으면 GUID에서, 없으면 `(hwnd, uid)`에서 만듭니다. **`hwnd` 기반 키는 앱을 다시 띄우면 바뀌므로 숨김이 풀립니다.** 볼륨과 배터리는 GUID가 있으므로(로그의 `guid=1`) 이번 목적에는 문제가 없습니다.

이 제약을 `ARCHITECTURE.md`의 트레이 절에 한 줄로 적으십시오. 지금 고치려 하지 마십시오.

## 2. 이중 프리멀티플라이를 검증하고 고친다

### 2-1. 무엇을 의심하는가

지난 라운드의 255 클램프로 검은 얼룩은 사라졌지만, 카카오톡 아이콘의 둥근 모서리에 **어두운 픽셀**이 남아 있습니다.

`icon_cache.cpp`의 `BitmapFromIcon` 마지막 줄이 후보입니다.

```cpp
return FinalizeIconBitmap(bmp, px, true);   // ← straight_alpha 를 true 로 고정
```

`true`를 넘기면 `FinalizeIconBitmap`이 `HasStraightAlpha` 판정을 건너뛰고 `StraightToPremul`을 **무조건** 실행합니다. 그런데 그 입력은 `DrawIconEx`가 32비트 DIB에 그린 결과입니다. GDI는 알파 채널이 있는 아이콘을 `AlphaBlend`로 그리므로 결과가 **이미 프리멀티플라이드**입니다. 그러면 한 번 더 곱해집니다.

알파가 128인 모서리 픽셀로 따지면 이렇게 됩니다.

```
원본(스트레이트)   (255, 220, 0)
GDI 가 프리멀티플  (128, 110, 0)
StraightToPremul   ( 64,  55, 0)   ← 두 번째 곱셈
PremulToStraight   (128, 110, 0)   ← 한 번만 나눔
```

밝기가 절반으로 남습니다. 둥근 모서리의 반투명 픽셀만 어두워지고 내부의 불투명 픽셀은 멀쩡한 것도 이것으로 설명됩니다. 라이트 테마에서만 눈에 띄는 것도 같은 이유입니다.

### 2-2. 확증부터 하십시오

**추측으로 고치지 마십시오.** `BitmapFromIcon`은 독 아이콘도 함께 쓰므로 잘못 바꾸면 독이 망가집니다.

`FIX-TRAY-ICON-CLICK.md` 1-5절과 같은 방식으로 임시 덤프를 두고, 같은 아이콘을 두 조건으로 뽑아 비교하십시오.

- 조건 A: 지금 그대로(`straight_alpha = true`)
- 조건 B: `HasStraightAlpha` 판정에 맡김(`straight_alpha = false`)

카카오톡처럼 둥근 모서리가 있는 아이콘과, 독에서 쓰는 아이콘을 **각각** 뽑아 흰 배경 위에서 비교하십시오. 확인할 것은 모서리의 반투명 픽셀이 원본 색조를 유지하는가입니다.

`HasStraightAlpha`가 이 입력에서 무엇을 돌려주는지도 로그로 남겨 함께 보고하십시오. 판정이 옳게 나오는지가 조건 B의 전제입니다.

### 2-3. 고치는 방향

측정 결과에 따라 정하고 근거를 보고하십시오.

- **조건 B가 양쪽 다 좋으면** `BitmapFromIcon`의 `true`를 `false`로 바꿉니다. 가장 간단하고 두 경로가 같은 규칙을 씁니다.
- **독이 조건 A에서만 좋으면** 두 경로를 갈라야 합니다. `BitmapFromIcon`에 `straight_alpha`를 인자로 받는 형태를 더하고, 기존 두 인자 형태는 지금 동작(`true`)을 유지해서 독의 호출부를 건드리지 않으십시오. 트레이 경로만 새 형태로 `false`를 넘깁니다.
- **둘 다 나아지지 않으면** 가설이 틀린 것입니다. 고치지 말고 `HasStraightAlpha`의 판정값과 덤프에서 관찰한 것을 그대로 보고하십시오. 다음 라운드에서 다시 봅니다.

확인이 끝나면 덤프 코드를 지우고 커밋 대상에서 빼십시오.

## 3. explorer 아이콘의 한계를 문서에 적는다

`ARCHITECTURE.md`의 가로채기 한계 목록에 다음을 더하십시오.

- explorer가 자기 `Shell_NotifyIcon`으로 등록하는 아이콘 가운데 일부는 클릭을 XAML 트리에서 처리하므로, 콜백 메시지를 보내도 반응하지 않는다. 볼륨과 배터리가 그렇고 블루투스는 정상 동작한다. 반응하지 않는 항목은 `트레이 아이콘` 하위 메뉴에서 숨긴다.

`RESEARCH-TRAY-REREGISTER.md` 2절의 2026-08-31 관찰에도 한 줄 이어 붙이십시오. 시스템 아이콘이 이 경로로 오기는 하지만 **활성화까지 되는 것은 아니라는** 사실이 이번에 드러났습니다.

## 4. 하지 않을 것

- 볼륨·배터리의 클릭을 동작시키려 하지 마십시오. UIA와의 하이브리드 활성화는 이번 범위가 아닙니다.
- 볼륨 위젯을 만들지 마십시오. 나중에 별도로 합니다.
- `tray_system_icons` 설정의 의미를 바꾸지 마십시오. 블루투스가 함께 사라집니다.
- 가로채기 항목에 `system_icon` 표시를 붙이지 마십시오. 1-1절의 이유로 쓸 수 없는 기준입니다.
- 키 생성 방식을 바꾸지 마십시오. 1-5절은 문서에만 적습니다.
- 선행 지시서들의 금지 사항은 그대로 유효합니다.
- **사용자 화면에 마우스나 키보드 입력을 합성하지 마십시오.**

## 5. 검증

### 5-1. Cursor가 직접 할 것

| 확인 항목 | 방법 |
|---|---|
| 빌드 | Release. 경고가 늘지 않아야 합니다 |
| 하위 메뉴 구성 | 메뉴를 만드는 경로를 로그로 확인하십시오. 항목 수와 각 항목의 체크 상태를 한 줄로 남기고, 확인 뒤 그 로그는 지우십시오 |
| 숨김 왕복 | 코드에서 키 하나를 `tray_hidden_keys`에 넣었다 뺐을 때 `settings.json`이 올바르게 갱신되는지 확인하십시오 |
| 덤프 비교 | 2-2절. 조건 A와 B를 나란히 놓고 직접 보십시오 |
| 독 회귀 | 2-2절. 독 아이콘이 나빠지지 않았는지 반드시 함께 보십시오 |

메뉴를 실제로 열어 보는 것은 사용자만 할 수 있습니다. 클릭을 합성하지 마십시오.

### 5-2. 사용자가 할 것

보고서에 다음 절차를 정리하십시오.

1. 상단바를 우클릭해 `트레이 아이콘` 하위 메뉴를 엽니다.
2. 목록에 일곱 항목이 나오고 전부 체크되어 있는지 봅니다.
3. `볼륨`과 `배터리`를 각각 눌러 체크를 해제합니다.
4. 상단바에서 두 아이콘이 사라지는지 봅니다.
5. 하위 메뉴를 다시 열어 두 항목이 체크 해제 상태로 남아 있는지 봅니다.
6. 하나를 다시 눌러 되살아나는지 봅니다.
7. 카카오톡 아이콘의 모서리가 라이트 테마에서 깨끗한지 봅니다.
