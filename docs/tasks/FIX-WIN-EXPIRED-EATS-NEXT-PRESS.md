# 작업 지시서: 만료 표시가 그 뒤의 Win 누름 한 번을 삼키는 것을 고친다

> 작업 당시의 진단과 지시를 남긴 기록입니다. 현재 코드의 설명이 아닙니다.

`FIX-WORKAREA-GUARD-AND-WIN-STALE.md` 2부의 후속입니다. 앞 지시서를 검수하다가 **지시서 자체의 설계 결함**을 확인했습니다. 구현은 지시대로 되어 있으므로 잘못은 지시한 쪽에 있습니다. 건드리는 파일은 `src/menu_bar.cpp` 하나입니다.

---

## 1. 무엇이 잘못되었는가

`g_win_expired` 는 만료가 일어난 뒤에 뒤늦게 도착하는 진짜 Win 뗌을 흘려보내려고 둔 표시입니다. 그런데 **그 뗌이 끝내 오지 않는 경우를 생각하지 않았습니다.** 애초에 뗌을 놓쳤기 때문에 만료가 일어난 것이므로, 오지 않는 쪽이 오히려 보통입니다.

표시가 참으로 남아 있는 채로 사용자가 Win 키를 새로 누르면 다음 순서가 됩니다.

1. Win down: `!g_win_held` 이므로 `g_win_down_tick` 을 새로 적고 `g_win_held` 를 세웁니다. **`g_win_expired` 는 참으로 남아 있습니다.**
2. Win up: 맨 앞의 `if (g_win_expired)` 에 걸려 표시만 지우고 `return 1` 로 끝납니다.
3. 곧 `kToggleStartMsg` 가 가지 않으므로 **시작 메뉴가 열리지 않습니다.**

만료가 한 번 일어날 때마다 그 뒤의 Win 누름 한 번이 조용히 사라집니다. 사용자에게는 시작 메뉴가 가끔 안 열리는 증상으로 보입니다.

## 2. 고칠 것

Win down 갈래에서 새 누름이 시작될 때 표시를 함께 지우십시오. 새로 누른 이상 앞선 주기의 뒤처리는 끝난 것입니다.

```cpp
    if (down) {
      if (!g_win_held) {
        g_win_down_tick = GetTickCount64();
        g_win_expired = false;
      }
      g_win_held = true;
```

`if (!g_win_held)` 안에 넣어야 합니다. **자동 반복이 이 훅에 도달하더라도 주기가 새로 시작될 때에만 지워지도록** 하려는 것입니다.

`ExpireStaleWin` 과 `ReleaseHeldWin` 과 Win up 갈래는 그대로 두십시오. `ReleaseHeldWin` 에는 `g_win_expired = true` 를 넣지 마십시오. 세션 잠금 해제에서도 불리는 함수이므로, 거기에서 표시를 세우면 그 뒤의 평범한 Win 누름이 이번과 똑같이 삼켜집니다.

## 3. 검증

1. Release 클린 빌드가 경고 없이 통과해야 합니다. **CMake 로 빌드하십시오.**
2. `LowLevelKeyboardProc` 안에 `Log` 호출이 없어야 합니다.
3. Win 단독 누름으로 시작 메뉴가 열리는지 **사용자에게 확인을 부탁하십시오.** 이 환경에서는 키보드 입력을 합성할 수 없습니다.

**빌드하려고 실행 중인 bamti 를 종료했다면, 끝난 뒤 반드시 WMI 로 다시 띄워 놓으십시오.**

## 4. 하지 말 것

- `g_win_expired` 를 없애지 마십시오. 만료 직후에 도착하는 뗌이 시작 메뉴를 여는 것을 막는 유일한 장치입니다.
- 1부(작업 영역 표식)의 코드는 건드리지 마십시오. 검증까지 끝났습니다.
- 이 지시서에 적히지 않은 정리나 개선을 함께 넣지 마십시오.
