# 작업 지시서: 드래그 중에도 오른쪽 위 코너가 동작하게 한다

> 작업 당시의 진단과 지시를 남긴 기록입니다. 현재 코드의 설명이 아닙니다.

`TASK-SHOW-DESKTOP-TOGGLE.md`(커밋 `aa6fbb4`)의 후속입니다. 건드리는 파일은 `src/menu_bar.cpp`와 `src/menu_bar.hpp`입니다.

---

## 1. 사용자가 실제로 원한 것

macOS의 핫 코너와 같은 흐름입니다.

1. Ctrl을 누른 채 상단바 오른쪽 끝에 올려 바탕 화면으로 넘어간다.
2. **바탕 화면의 파일을 끌기 시작한다.**
3. **끌고 있는 채로** 다시 오른쪽 끝에 올려 원래 창으로 돌아온다.
4. 끌고 온 항목을 그 창에 떨어뜨린다.

지금은 3번에서 아무 일도 일어나지 않습니다.

---

## 2. 원인

**코너 판정이 `WM_MOUSEMOVE`로만 돌아갑니다.**

`MenuBar::UpdateDesktopPeek`를 부르는 곳은 `WM_MOUSEMOVE` 처리부 한 곳뿐입니다. 그런데 파일을 끄는 동안에는 **끄는 쪽 프로세스가 마우스를 캡처한 채 모달 드래그 루프(`DoDragDrop`)를 돌립니다.** 마우스 메시지는 캡처를 쥔 창으로만 가므로 상단바 창에는 한 건도 오지 않습니다.

즉 판정이 틀린 것이 아니라 **판정이 아예 실행되지 않습니다.**

`WM_MOUSELEAVE`도 오지 않으므로 걸쇠(`peek_latched_`)가 풀리지 않은 채로 남아 있을 수도 있습니다. 그 상태라면 나중에 마우스를 움직여도 다시 발동하지 않습니다. 이 점도 함께 확인하십시오.

---

## 3. 고치는 방향: 코너 감시를 창 메시지에서 떼어낸다

커서 위치를 **창 메시지가 아니라 전역 좌표로** 봅니다. `GetCursorPos`는 캡처와 무관하게 언제나 참값을 돌려주므로 드래그 중에도 동작합니다.

그렇다고 상시 타이머를 돌리면 아무 일도 없는 동안 CPU를 깨웁니다. **이미 있는 저수준 키보드 훅을 방아쇠로 씁니다.**

`LowLevelKeyboardProc`는 시스템 전역이라 **드래그 중에도 키 이벤트를 받습니다.** 여기에서 Ctrl을 보고 감시를 켜고 끕니다.

### 3-1. 훅에 Ctrl 감지를 더한다

`src/menu_bar.cpp`의 `LowLevelKeyboardProc`에 다음을 더하십시오.

- `vk`가 `VK_CONTROL`, `VK_LCONTROL`, `VK_RCONTROL` 중 하나이고 `down`이면 `PostMessageW(g_menu_bar->hwnd(), kCornerWatchMsg, 1, 0)`
- 같은 키가 `up`이면 `PostMessageW(g_menu_bar->hwnd(), kCornerWatchMsg, 0, 0)`

**Ctrl을 삼키면 안 됩니다.** 반드시 `CallNextHookEx`의 반환값으로 빠져나가십시오. Win 키 갈래처럼 `return 1`을 하면 시스템 전체에서 Ctrl이 먹통이 됩니다.

같은 키가 눌린 채로 자동 반복되면 `down`이 계속 들어옵니다. 이미 켜져 있으면 다시 켜지 않도록 하십시오.

새 메시지는 기존 방식대로 더합니다.

```cpp
inline constexpr UINT kCornerWatchMsg = WM_APP + 10;
```

`WM_APP + 9`까지 쓰고 있으므로 10이 비어 있습니다. 확인하고 쓰십시오.

### 3-2. 코너 감시 타이머

`kCornerWatchMsg`를 받으면 `wparam`에 따라 타이머를 켜고 끕니다.

```cpp
constexpr UINT_PTR kCornerWatchTimerId = 7;
constexpr UINT kCornerWatchMs = 60;
```

기존 타이머 아이디가 6까지 쓰이고 있으므로 7이 비어 있습니다.

타이머가 돌 때마다 다음을 합니다.

1. `GetCursorPos`로 화면 좌표를 얻는다.
2. `GetWindowRect(hwnd_)`로 상단바의 화면 사각형을 얻는다.
3. 커서가 그 사각형 안이고 `pt.x >= rc.right - DipToPx(kPeekZoneDip, Dpi())`이면 코너 안이다.
4. 코너 안이면 지금의 뜸과 걸쇠 논리를 그대로 태운다. 밖이면 걸쇠를 풀고 뜸 타이머를 죽인다.

Ctrl 확인은 `DesktopPeekWanted`가 이미 `GetAsyncKeyState`로 하고 있으므로 그대로 둡니다. 훅이 놓치는 경우(다른 창이 Ctrl을 삼킨 경우 등)에 대한 안전망이 됩니다.

Ctrl에서 손을 떼면 훅이 `wparam=0`을 보내므로, 그때 **타이머를 죽이고 걸쇠를 풉니다.** 지금 `kDesktopPeekPollTimerId`가 하던 일을 이 타이머가 흡수하므로 **폴링 타이머는 지우십시오.**

### 3-3. `WM_MOUSEMOVE` 경로를 걷어낸다

`WM_MOUSEMOVE`의 `UpdateDesktopPeek(pt)` 호출을 지웁니다. 경로가 둘이면 드래그 중과 아닐 때의 동작이 갈라집니다. **한 경로로 통일하십시오.**

`WM_MOUSELEAVE`와 `BeginReorder`와 `SetFullscreenOccluded`에서 걸쇠를 푸는 자리는 그대로 두십시오. 안전망입니다.

`PeekZoneHit`는 클라이언트 좌표를 받고 있습니다. 화면 좌표를 받도록 바꾸거나 새 함수를 만드십시오. 남는 함수와 `peek_pt_`가 쓰이지 않게 되면 함께 지웁니다.

### 3-4. 놀고 있을 때의 비용

**Ctrl을 누르고 있는 동안에만 타이머가 돕니다.** 평소에는 한 번도 깨지 않습니다. 이 설계의 요점이므로 상시 타이머로 바꾸지 마십시오.

## 4. 드래그 중에 토글이 실제로 되는지 측정한다

**이것이 이 작업의 가장 큰 미지수입니다.**

다른 프로세스가 캡처를 쥔 모달 드래그 루프 안에서 `IShellDispatch4::ToggleDesktop`이 동작하는지 확인되지 않았습니다. 셸이 거부하거나 무시할 수 있습니다.

`ToggleDesktop`의 `HRESULT`와, 호출 전후로 아무 창 하나의 `IsIconic` 값을 로그로 남기십시오.

```cpp
Log(L"peek", L"toggle hr=0x%08lx iconic_before=%d iconic_after=%d", ...);
```

**동작하지 않으면 대체 경로를 시험하십시오.**

```cpp
PostMessageW(FindWindowW(L"Shell_TrayWnd", nullptr), WM_COMMAND, 419, 0);
```

Windows가 예전부터 쓰는 바탕 화면 보기 명령입니다. **메시지를 보내는 방식이라 캡처와 무관하게 explorer가 자기 차례에 처리하므로 드래그 중에도 통할 가능성이 높습니다.**

bamti가 작업 표시줄을 감춰도 그 창은 파괴되지 않고 숨겨질 뿐인 것을 확인했습니다. 핸들이 유효하고 `IsWindowVisible`만 거짓입니다.

**둘 중 실제로 동작하는 쪽을 남기십시오.** 둘 다 되면 문서화된 `ToggleDesktop`을 씁니다. 어느 쪽을 왜 골랐는지 보고에 적으십시오.

## 5. 검증

이 환경에서는 마우스와 키보드 입력을 합성할 수 없습니다. **사용자 화면에 입력을 밀어 넣으려고 하지 마십시오.** 실제 드래그가 필요한 항목은 코드 경로를 설명하고 사용자 확인으로 넘기되, **4절의 측정만은 반드시 로그로 남기십시오.**

1. Release 클린 빌드가 경고 없이 통과해야 합니다.
2. **훅이 Ctrl을 삼키지 않는지.** 아무 편집기에서 Ctrl+C와 Ctrl+V가 그대로 되어야 합니다. **이것부터 확인하십시오.** 여기서 실수하면 컴퓨터를 쓸 수 없게 됩니다.
3. **타이머가 평소에는 돌지 않는지.** Ctrl을 누르지 않은 상태에서 `kCornerWatchTimerId`가 걸려 있지 않아야 합니다. 로그로 확인하십시오.
4. **드래그가 아닐 때의 회귀.** Ctrl을 누른 채 오른쪽 끝에 300밀리초 머물면 바탕 화면으로 넘어가고, 벗어났다 다시 오면 돌아와야 합니다. 머무는 동안 깜빡이면 안 됩니다.
5. **드래그 중 동작.** 바탕 화면의 파일을 끌기 시작한 뒤, 끌고 있는 채로 Ctrl을 누르고 오른쪽 끝에 머무르십시오. 창이 돌아와야 하고, 그 창에 떨어뜨릴 수 있어야 합니다.
6. **걸쇠 잔류.** 5번을 한 뒤 마우스를 다른 곳으로 옮겼다가 다시 Ctrl+코너로 오면 또 발동해야 합니다. 걸쇠가 풀리지 않은 채 남으면 안 됩니다.
7. **재정렬 회귀.** Ctrl로 위젯을 끌어 순서를 바꾸는 기능이 그대로여야 하고, 오른쪽 끝까지 끌어도 발동하면 안 됩니다.

검증하겠다고 사용자의 창을 최소화한 채로 두지 마십시오. 확인한 뒤에는 반드시 되돌려 놓으십시오.

레지스트리에 쓰는 확인 절차는 넣지 마십시오.
