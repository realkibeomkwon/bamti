# 작업 지시서: 걸러낸 항목 로그가 툴팁마다 쌓이는 문제를 고친다

> 작업 당시의 진단과 지시를 남긴 기록입니다. 현재 코드의 설명이 아닙니다.

건드리는 파일은 `src/tray_mirror.cpp` 와 `src/tray_mirror.hpp` 두 개입니다.

---

## 1. 앞선 수정은 성공했습니다

`FIX-FILL-OWNER-REGRESSION.md` 의 수정으로 회귀가 잡혔습니다. 13분 가동 기준 실측값입니다.

| 항목 | 회귀 시점 | 지금 |
| --- | --- | --- |
| 코어 하나 기준 CPU | 11.3% | **1.4%** |
| 최악 열거 시간 | 41초 | **1.34초** |
| `fill enum slow` | 11분에 55회 | 13분에 12회 |
| `fill owners pruned` | — | 0회 (상한에 걸리지 않음) |

**41초 열거는 사라졌습니다.** 2-2 에서 원인이 확정되지 않았다고 남겨 둔 항목은 이것으로 닫습니다.

---

## 2. 남은 결함

`fill skip unknown` 이 13분 동안 **105회** 나왔습니다. 전체 로그 915줄 가운데 11퍼센트입니다.

```
20:06:28.588 [tray] fill skip unknown tip="작업 관리자 CPU 6% 메모리 40% 디스크 4% 네트워크 0%"
20:06:33.588 [tray] fill skip unknown tip="작업 관리자 CPU 7% 메모리 40% 디스크 3% 네트워크 0%"
20:06:43.630 [tray] fill skip unknown tip="작업 관리자 CPU 7% 메모리 40% 디스크 4% 네트워크 0%"
```

전부 작업 관리자입니다. `fill_skip_unknown_` 은 "툴팁마다 한 번씩만 남기라"는 지시에 따라 툴팁을 열쇠로 하는데, **툴팁이 매번 다르므로 매번 처음 보는 항목이 됩니다.**

결과는 둘입니다.

1. 5초마다 로그가 한 줄씩 쌓입니다.
2. `fill_skip_unknown_` 집합이 **무한히 커집니다.** `fill_owners_` 에서 방금 고친 것과 같은 종류의 누수가 로그 쪽에 남아 있습니다.

### 왜 작업 관리자가 주인을 못 찾는가

두 백엔드가 같은 아이콘에 서로 다른 툴팁을 보고합니다.

```
가로채기 : tips="...|작업 관리자|CPU 9% 메모리 40% 디스크 3% 네트워크 0%|작업 관리자|..."
UIA      : tip="작업 관리자 CPU 6% 메모리 40% 디스크 4% 네트워크 0%"
```

UIA 는 접근성 이름과 툴팁을 이어 붙여 돌려줍니다. **툴팁 문자열로 두 백엔드를 잇는 방식의 구조적 한계입니다.** 카카오톡처럼 양쪽이 같은 문자열인 경우에만 이어집니다.

이 한계 자체는 이번에 고치지 않습니다. 로그와 메모리만 막습니다.

## 3. 무엇을 고치는가

### 3-1. 먼저 재십시오

UIA 항목의 `TrayIconInfo::key` 가 같은 아이콘에서 안정적인지 확인하십시오. 열거를 여러 번 돌려 같은 아이콘의 key 가 유지되는지 보면 됩니다.

- **안정적이면** `fill_skip_unknown_` 의 열쇠를 툴팁 대신 key 로 바꾸십시오. 그것으로 끝입니다.
- **안정적이지 않으면** 3-2 로 가십시오.

측정 결과를 보고하십시오.

### 3-2. key 가 안정적이지 않을 때

집합에 상한을 두고 로그 빈도를 제한하십시오.

- `fill_skip_unknown_` 이 128 개를 넘으면 통째로 비웁니다.
- 같은 로그를 **1분에 한 번**만 남깁니다. 마지막으로 남긴 시각을 기억해 두고 그 안에 다시 오면 건너뜁니다.
- 억눌린 횟수를 함께 실으십시오.

```
[tray] fill skip unknown n=%u tip="%s"
```

`n` 은 직전 로그 이후 걸러낸 횟수입니다. 정보를 잃지 않으면서 줄 수를 줄이는 것이 목적입니다.

---

## 4. 아직 검증되지 않은 것

`fill key=` 가 새 빌드에서 **0회**입니다. 보충 항목이 한 번도 게시되지 않았으므로 다음 둘을 확인할 수 없었습니다.

1. 카카오톡을 완전히 종료했을 때 `K` 가 나타나지 않는지
2. 보충 항목이 게시될 때 글자가 아니라 **아이콘**으로 보이는지

3절을 마친 뒤 사용자에게 확인을 부탁하십시오. **사용자 화면에 입력을 합성하지 마십시오.**

가로채기가 지금 모든 아이콘을 잡고 있어서 보충이 필요 없는 상태일 수도 있습니다. 그렇다면 그 사실을 로그로 확인해 보고하십시오. 억지로 보충을 발생시키려 하지 마십시오.

---

## 5. 검증

1. 빌드 후 **작업 관리자를 켠 채로** 10분 이상 둡니다.
2. `fill skip unknown` 이 10분에 몇 회인지 세십시오. **한 자릿수여야 합니다.**
3. 코어 하나 기준 CPU 가 1.4퍼센트 수준에서 나빠지지 않았는지 재십시오.
4. `fill enum slow` 와 최악 열거 시간이 나빠지지 않았는지 보십시오. 직전 최악값은 1344ms 입니다.
5. 4절의 두 항목을 사용자에게 부탁해 확인하십시오.

## 6. 건드리지 말 것

- `fill_owners_`, `fill_exe_by_owner_`, `fill_tip_by_owner_` 의 열쇠 관리. 방금 고쳤고 잘 돌고 있습니다
- `IsWindow` 와 PID 대조로 유령을 걸러내는 규칙
- `FillPngForExe` 의 아이콘 캐시
- `kFillRefreshMs` 5초 주기와 `TakeStartupFillPulse` 펄스
- 두 백엔드의 툴팁 표기가 다른 문제. 이번 범위가 아닙니다
- `InvokeByExe` 와 `Dock::RevealDockApp`
- `src/menu_bar.cpp` 전체
