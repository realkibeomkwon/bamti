# 작업 지시서: 코너 감지 영역을 오른쪽 여백만큼 넓힌다

> 작업 당시의 진단과 지시를 남긴 기록입니다. 현재 코드의 설명이 아닙니다.

`FIX-WIN-HELD-STALE.md`(커밋 `ebc17f1`)의 후속입니다. 건드리는 파일은 `src/menu_bar.cpp` 하나이고, 바꾸는 것은 상수 하나입니다.

---

## 1. 측정: 실패한 회차는 커서가 코너에 들어오지 못한 것이다

사용자가 "두 번째부터 안 된다"고 보고했습니다. 로그를 보면 **전환 자체는 두 번 다 성공했습니다.**

```
10:34:50.972 watch on=1
10:34:51.302 corner in=1 x=5119 y=0 right=5120
10:34:51.302 dwell arm
10:34:51.426 dwell fire
10:34:51.629 MinimizeAll     hr=0x00000000 iconic_before=0 iconic_after=1
10:34:51.751 corner in=0 x=5104 y=10 right=5120
10:34:51.751 unlatch reason=corner-left
10:34:52.127 corner in=1 x=5119 y=0 right=5120
10:34:52.250 dwell fire
10:34:52.443 UndoMinimizeALL hr=0x00000000 iconic_before=1 iconic_after=0
```

반면 실패한 회차에는 `corner in=1`이 아예 없습니다.

```
10:39:03.552 watch on=1
10:39:03.911 watch on=0     ← 359밀리초 동안 코너 진입 기록이 없다
```

**판정 논리는 옳고, 커서가 영역 안에 들어오지 못한 것입니다.**

성공한 회차의 좌표는 `x=5119`, 곧 화면 맨 끝 픽셀입니다. 실패로 이어진 이탈 좌표는 `x=5104`로 오른쪽 끝에서 16픽셀 떨어져 있습니다.

`kPeekZoneDip = 8`이고 이 화면은 배율이 150%이므로 **감지 영역의 실제 너비가 12픽셀뿐입니다.** 5120픽셀 폭의 화면에서 마지막 12픽셀만 유효합니다. 마우스를 오른쪽 끝까지 밀어붙이면 걸리지만, 조금이라도 못 미치면 아무 일도 일어나지 않습니다.

---

## 2. 고칠 것

`src/menu_bar.cpp`의 상수 하나입니다.

```cpp
constexpr int kPeekZoneDip = 8;   →   constexpr int kPeekZoneDip = 14;
```

14를 고른 이유가 있습니다. `src/bar_layout.cpp`의 `kPadRightDip = 14.0f`가 시계 오른쪽에 남기는 **빈 여백의 폭과 정확히 같습니다.** 그러므로 영역을 넓혀도 시계를 비롯한 어떤 세그먼트의 적중 판정과도 겹치지 않습니다.

150% 배율에서 12픽셀이 21픽셀이 됩니다. **이 이상 넓히지 마십시오.** 시계 위에서 발동하기 시작합니다.

`bar_layout.cpp`는 건드리지 마십시오. 두 값이 같은 뜻이라는 것을 주석 한 줄로만 남기십시오.

---

## 3. 하지 말 것

**걸쇠(`peek_latched_`)를 건드리지 마십시오.** 한 번 발동한 뒤 다시 발동하려면 코너를 벗어났다가 들어와야 하는 것은 의도된 동작입니다. 사용자가 앞서 "머무는 동안 깜빡인다"고 지적한 것을 이 걸쇠로 막았습니다.

발동 뒤 일정 시간이 지나면 자동으로 다시 발동하게 만들지 마십시오. 코너에 마우스를 둔 채 두면 창이 느리게 오르내리게 됩니다.

뜸(`kDesktopPeekDwellMs = 120`)과 감시 주기(`kCornerWatchMs = 30`)도 그대로 두십시오.

---

## 4. 검증

1. Release 클린 빌드가 경고 없이 통과해야 합니다.
2. `kPeekZoneDip`이 14이고 다른 상수가 바뀌지 않았는지 확인하십시오.
3. **시계 위에서 발동하지 않는지.** Ctrl을 누른 채 시계 글자 위에 머물러도 전환이 일어나면 안 됩니다. 이 항목이 값을 너무 키우지 않았음을 확인합니다.
4. 나머지는 사용자 확인으로 넘기십시오. `corner in=1`이 이전보다 쉽게 찍히는지가 판정 근거입니다.

이 환경에서는 마우스와 키보드 입력을 합성할 수 없습니다. 사용자 화면에 입력을 밀어 넣으려고 하지 마십시오.

**빌드하려고 실행 중인 bamti를 종료했다면, 끝난 뒤 반드시 다시 띄워 놓으십시오.**

레지스트리에 쓰는 확인 절차는 넣지 마십시오.
