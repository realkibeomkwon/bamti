# 수정 지시서: 마스킹 문자를 바꾸고, 입력할 때 눈 단추가 지워지는 것을 고친다

> 작업 당시의 진단과 지시를 남긴 기록입니다. 현재 코드의 설명이 아닙니다.

`FIX-WIFI-PASSWORD-REVEAL.md` 구현물을 사용자가 확인한 뒤 나온 요청 두 가지입니다.
건드리는 파일은 `src/wifi_password.cpp`입니다.

캐럿 정렬과 라벨과 눈 단추의 동작은 확인을 마쳤습니다. **그 부분은 건드리지 마십시오.**

---

## 1. 마스킹 문자를 `●`로 바꾼다

지금은 `*`가 찍힙니다. `U+25CF`(BLACK CIRCLE)로 바꾸십시오.

- Windows의 암호 상자가 쓰는 문자이고, 맥도 같은 자리에 점을 찍습니다. `*`는 옛 대화 상자의 어법입니다.
- `Segoe UI`에 이 글자가 있습니다. 네모로 나오면 글꼴이 잘못 걸린 것이니 그때 보고하십시오.

지금 코드는 `EM_GETPASSWORDCHAR`로 시스템이 정한 문자를 읽어 `mask_char_`에 담고 있습니다.
**읽는 대신 우리가 정한 값을 넣으십시오.** 창을 만든 직후 한 번입니다.

```cpp
mask_char_ = 0x25CF;
SendMessageW(edit_, EM_SETPASSWORDCHAR, mask_char_, 0);
```

- `ToggleReveal`이 가리기로 되돌릴 때 쓰는 값도 이것이어야 합니다. 이미 `mask_char_`를 쓰고 있으니
  대입 자리만 바꾸면 됩니다.
- 설정한 뒤 `InvalidateRect(edit_, nullptr, TRUE)`를 부르십시오. 이미 찍힌 글자는 저절로 바뀌지
  않습니다.

## 2. 입력하면 눈 단추가 지워지는 것

### 2-1. 원인

사용자가 이렇게 보고했습니다. **눈 위에 마우스를 올려 둔 채로 글자를 입력하면 눈이 사라지고 그
자리가 비어 보입니다.**

`EDIT` 컨트롤의 폭이 행의 오른쪽 끝까지 뻗어 있어서 눈 단추 자리를 덮고 있는 것이 원인입니다.

```cpp
const int edit_w = (std::max)(0, static_cast<int>(row.right) - inset - edit_left);
...
SendMessageW(edit_, EM_SETMARGINS, EC_RIGHTMARGIN, MAKELPARAM(0, right_margin));
```

`EM_SETMARGINS`는 **글자를 안쪽으로 밀 뿐 컨트롤의 영역을 줄이지 않습니다.** 눈은 부모 창이
그리는데 그 위에 자식 컨트롤이 겹쳐 있으니, 글자를 칠 때마다 컨트롤이 자기 배경으로 그 자리를
덮습니다. 호버 상태에서는 원형 강조까지 함께 지워져 더 눈에 띕니다.

### 2-2. 수정

**컨트롤이 눈 자리를 침범하지 않게 하십시오.** 다시 그릴 때 부모가 눈을 덧그리는 방식으로
때우지 마십시오. 깜빡이고, 다시 그리는 계기를 하나라도 놓치면 같은 증상이 돌아옵니다.

```
edit_w = 눈 단추의 왼쪽 - 8 DIP - edit_left
```

- 컨트롤의 오른쪽 경계가 눈 단추의 왼쪽보다 왼쪽에 있어야 합니다. 겹치는 픽셀이 하나도 없어야
  합니다.
- 폭을 줄였으므로 `EM_SETMARGINS`의 오른쪽 여백은 이제 필요 없습니다. 0으로 두거나 호출을
  지우십시오. 남겨 두면 글자 영역이 두 번 줄어 입력란이 쓸데없이 좁아집니다.
- 눈 단추의 자리를 계산하는 `EyeRect()`가 이미 있으니 그 값을 그대로 쓰십시오. 같은 수치를 두 곳에
  따로 적으면 나중에 어긋납니다.

### 2-3. 함께 확인할 것

- 눈 자리를 클릭했을 때 여전히 `ToggleReveal`이 불리는지 보십시오. 컨트롤 폭이 줄면 그 자리의
  마우스 메시지가 부모에게 가므로 히트 테스트가 오히려 단순해집니다.
- 긴 암호를 넣었을 때 글자가 컨트롤 오른쪽 경계에서 잘리는지 보십시오. 눈 아래로 흘러 들어가면
  안 됩니다.

## 3. 검증

빌드는 Release 클린 빌드로 하고 경고가 없어야 합니다. **앱이 떠 있으면 링크가 막히므로
(`LNK1104`) 먼저 종료하십시오.** 이 저장소의 빌드 트리는 `out/cmake-debug`입니다.

1. **마스킹 문자.** 글자를 넣어 `●`가 찍히는지 보십시오. 네모가 나오면 글꼴 문제이니 보고하십시오.
2. **눈이 지워지지 않는지.** 마우스를 눈 위에 올려 둔 채로 여러 글자를 이어서 치십시오. 눈과 호버
   강조가 그대로 있어야 합니다. **이것이 이번 수정의 핵심입니다.**
3. **지우기와 붙여넣기.** 백스페이스로 지울 때와 Ctrl+V로 붙여넣을 때도 눈이 남아 있는지 보십시오.
4. **보이기 상태에서도.** 눈을 눌러 글자가 드러난 상태에서 같은 것을 확인하십시오.
5. **긴 암호.** 40자를 넣어 글자가 눈을 침범하지 않는지 보십시오.
6. **단추가 여전히 동작하는지.** 눌러서 보이기와 가리기가 바뀌고, 누른 뒤 바로 타자가 입력란에
   들어가는지 확인하십시오.
7. **배율 세 가지와 테마 두 가지.** 100%, 150%, 200%에서, 라이트와 다크에서 각각 보십시오.

### 검증 방법에 관한 제약

**사용자의 화면에 마우스 클릭이나 키 입력을 합성하지 마십시오.** 지난 회차에 `wifi_field_verify.exe`
같은 도구로 상단바를 클릭하고 키를 보냈는데, 그 화면은 사용자가 실제로 쓰고 있는 바탕 화면입니다.

- 코드를 읽어 판정할 수 있는 것은 코드로 판정하십시오. 이번 건은 컨트롤의 사각형과 눈의 사각형이
  겹치는지를 계산으로 확인할 수 있습니다. **그 두 사각형의 좌표를 로그로 찍어 보고하십시오.**
- 눈으로 봐야 하는 항목은 준비만 해 두고 사용자에게 부탁하십시오. 무엇을 눌러 무엇을 봐야 하는지
  적어서 넘기면 됩니다.
- Wi-Fi를 끄거나 다른 망으로 갈아타지 마십시오. 세션이 끊깁니다.

---

## 4. 보고할 것

- `EDIT` 컨트롤의 사각형과 눈 단추의 사각형 좌표. 150% 배율 기준으로 두 값을 함께 적어
  겹치지 않음을 보이십시오.
- `EM_SETMARGINS`를 지웠는지 0으로 두었는지.
- 마스킹 문자가 `●`로 찍힌 화면. 이 화면은 앱을 띄운 뒤 사용자에게 부탁해 받으십시오.
- 사용자가 직접 확인해야 할 항목의 목록. 무엇을 눌러 무엇을 보면 되는지 한 줄씩 적으십시오.
