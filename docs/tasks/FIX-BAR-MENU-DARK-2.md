# 보정 지시서: 상단바 메뉴 교체 뒤 남은 두 가지

> 작업 당시의 진단과 지시를 남긴 기록입니다. 현재 코드의 설명이 아닙니다.

`FIX-BAR-MENU-DARK.md`의 구현(커밋 `e812449`)을 검수한 결과입니다. 두 결함 모두 작지만, 하나는 사용자에게 보이는 회귀입니다.

구현 자체는 지시서를 충실히 따랐습니다. 서브메뉴 연동, `PostMessageW`를 통한 명령 전달, 다른 팝업을 열 때 `SetAfterTick`을 지우는 처리까지 정확합니다. 특히 `OpenOverflow`, `ShowControlCenter`, `ShowClockFlyout`, `ShowClockMenu`, `OpenStatusPanel` 다섯 곳에 `CloseTraySubmenu`와 `SetAfterTick(nullptr, nullptr)`을 함께 넣은 것은 지시서에 없던 판단이며, `status_popup_`을 공유하는 구조에서 반드시 필요한 처리였습니다.

건드리는 파일은 `src/bar_menu.cpp`와 `src/menu_bar.cpp`입니다.

---

## 1. 긴 안내 문구가 말줄임표로 잘린다

### 1-1. 증상

상단바의 트레이 아이콘을 우클릭했을 때 나오는 안내 문구가 끝까지 보이지 않고 잘립니다. 교체 전 Win32 메뉴는 전체 문구를 보여 주었으므로 이것은 회귀입니다.

### 1-2. 원인

`src/bar_menu.cpp`의 `kMenuMaxWidthDip`이 360으로 잡혀 있습니다. 이 값은 지시서에서 제가 지정한 것이고, 실제 문구 길이를 재지 않고 어림한 값이었습니다.

Segoe UI 13px 기준으로 문구의 실제 폭을 재면 다음과 같습니다.

| 문구 | 텍스트 폭 |
|---|---|
| 숨긴 아이콘도 미러합니다. 클릭 반응이 없으면 알림 영역 잠시 표시로 여세요 | 441 dip |
| 위젯 보드 단추 (이 PC에서 사용할 수 없습니다) | 269 dip |
| 앱 메뉴는 알림 영역 잠시 표시로 엽니다 | 229 dip |
| 트레이 아이콘 가로채기(실험) | 171 dip |

`Measure`가 요구하는 창 폭은 `text_w + pad * 2 + text_pad * 2 + check_w + arrow_w`이므로, 가장 긴 문구에는 `441 + 12 + 24 + 16 + 14 = 507` dip이 필요합니다.

### 1-3. 수정

`src/bar_menu.cpp`의 상수를 다음과 같이 바꾸십시오.

```cpp
constexpr int kMenuMaxWidthDip = 520;
```

화면 논리 폭이 3413 dip이므로 520 dip 메뉴는 전체의 15% 남짓이며 부담이 되지 않습니다. `Place`가 화면 오른쪽 경계를 이미 보정하고 있으므로 화면 가장자리에서 열어도 넘치지 않습니다.

문구 자체는 다듬지 마십시오. 이번 작업은 표시 방식만 바꿉니다.

## 2. `MenuBar::Create` 안에 도달하지 않는 코드가 있다

### 2-1. 증상

동작에는 영향이 없지만, 절대 참이 되지 않는 조건문이 남아 있습니다.

### 2-2. 원인

`src/menu_bar.cpp`의 `MenuBar::Create`에서 `dark_ = ShellUsesDarkMode();` 바로 뒤, 아직 `CreateWindowExW`를 부르기도 전에 다음 블록이 들어갔습니다.

```cpp
  if (status_popup_.IsOpen() && bar_menu_ != nullptr) {
    bar_menu_->SetDark(dark_);
    status_popup_.SetDark(dark_);
    status_popup_.Present();
  }

  hwnd_ = CreateWindowExW(...);
```

이 시점에는 `status_popup_`이 아직 `Create`되지 않았고 `bar_menu_`도 비어 있으므로 조건이 항상 거짓입니다. `FIX-BAR-MENU-DARK.md` 4-5절에서 제가 "`dark_ = ShellUsesDarkMode();`가 실행되는 자리(`src/menu_bar.cpp:283`과 `442`) 뒤에서"라고 적은 것이 부정확했습니다. 283행은 초기화 경로여서 갱신할 대상이 존재하지 않습니다.

테마 전환을 실제로 처리하는 것은 442행 쪽에 들어간 블록이며, 그 코드는 올바릅니다.

### 2-3. 수정

`MenuBar::Create` 안에 들어간 위 네 줄을 지우십시오. 442행 쪽 블록은 그대로 두십시오.

## 3. 검증

1. `out/cmake-debug` 구성으로 빌드가 경고 없이 통과해야 합니다. **`bamti.exe`가 실행 중이면 링크 단계에서 `LNK1168`이 납니다.** 실행 중인 인스턴스를 먼저 종료한 뒤 빌드하십시오.
2. 상단바의 트레이 아이콘을 우클릭했을 때 안내 문구 세 줄이 잘리지 않고 끝까지 보여야 합니다. 이 확인은 입력을 합성하지 말고 사용자에게 부탁하십시오.
3. 상단바 빈 곳을 우클릭했을 때의 메뉴 폭이 이전보다 지나치게 넓어지지 않았는지 함께 확인받으십시오. 가장 긴 항목이 "위젯 보드 단추 (이 PC에서 사용할 수 없습니다)"이므로 폭은 330 dip 안팎에 머물러야 합니다.
4. 다크 모드와 라이트 모드 전환은 직접 하지 마십시오. 확인이 필요하면 사용자에게 설정 앱에서 바꿔 달라고 부탁하십시오.
