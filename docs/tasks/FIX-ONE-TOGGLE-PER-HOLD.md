# 작업 지시서: 한 번 누르는 동안 전환은 한 번만 한다

> 작업 당시의 진단과 지시를 남긴 기록입니다. 현재 코드의 설명이 아닙니다.

`FIX-RESTORE-TARGET-LIFETIME.md`(커밋 `1f0eebe`)의 후속입니다. 건드리는 파일은 `src/menu_bar.cpp`와 `src/menu_bar.hpp`입니다.

---

## 1. 측정: 재무장 구역으로는 막지 못했다

`ee4884b`에서 넣은 재무장 구역(96 DIP)이 반복 전환을 막을 것이라고 판단했습니다. **그 판단이 틀렸습니다.** 새로 넣은 `[peek] toggle` 로그로 Ctrl 유지 구간마다 전환 횟수를 셌습니다.

| 구간 | 시각 | 전환 횟수 |
| --- | --- | --- |
| 1 | 15:31:57 ~ 15:31:58 | 1 |
| 2 | 15:32:00 ~ 15:32:10 | **9** |
| 3 | 15:32:18 | 1 |
| 5 | 15:32:26 ~ 15:32:29 | 2 |
| 6 | 15:32:29 ~ 15:32:36 | 4 |

2번 구간에서 Ctrl을 9초 남짓 누르고 있는 동안 전환이 **아홉 번** 일어났습니다. 대략 1초에 한 번꼴입니다.

```
15:32:01.364 toggle shown=1   (복귀)
15:32:02.613 toggle shown=0   (최소화)
15:32:03.737 toggle shown=1   (복귀)
15:32:04.670 toggle shown=0   (최소화)
15:32:05.843 toggle shown=1   (복귀)
...
```

## 2. 내가 근거를 잘못 읽었다

앞 지시서는 다음 줄을 걸쇠가 풀린 지점으로 읽었습니다.

```
13:49:37.144 corner in=0 x=5096 y=20 right=5120
```

**이 줄은 걸쇠가 풀린 지점이 아닙니다.** 코너 구역(14 DIP)을 벗어난 첫 틱을 남기는 줄일 뿐입니다. 걸쇠는 그보다 훨씬 멀리 나갔을 때 풀립니다. 곧 "끝에서 24픽셀만 움직여도 풀린다"는 진단은 근거가 없었고, 96 DIP이면 충분하다는 계산도 함께 무너집니다.

**사용자의 실제 동작은 손 떨림이 아니라 큰 왕복입니다.** 코너를 짚고, 화면을 보려고 커서를 한참 아래로 내렸다가, 다시 코너로 올라옵니다. 이 왕복은 재무장 구역이 얼마나 넓든 넘어섭니다. 96을 200으로 키워도 같은 일이 반복될 뿐입니다.

**거리로는 이 문제를 풀 수 없습니다.**

## 3. 두 번째 증상도 같은 뿌리에서 나온다

사용자가 "복귀했을 때 최상위 창이 달라진다"고 보고했습니다. 반복 전환이 되살릴 창을 고착시킵니다.

```
최소화 → 되살릴 창으로 A를 기억
복귀   → A를 맨 앞으로 올리고 기억을 비움
최소화 → 이때 전경은 방금 우리가 올린 A이므로 다시 A를 기억
```

한 번 어긋난 뒤로는 **우리가 직전에 올린 창**만 계속 기억합니다. 사용자가 실제로 쓰던 창은 두 번 다시 후보가 되지 못합니다. 로그에서 되살릴 창이 계속 `CASCADIA_HOSTING_WINDOW_CLASS` 하나로만 남는 것이 그 증거입니다.

**전환을 한 번으로 묶으면 이 고착도 함께 사라집니다.** 그래서 이번에는 되살릴 창 쪽을 건드리지 않습니다.

---

## 4. 고칠 것: 한 번의 Ctrl 유지에 전환 한 번

`MenuBar`에 상태를 하나 더하십시오.

```cpp
bool peek_toggled_in_hold_ = false;
```

**`StartDesktopPeek`의 맨 앞**에서 이 값이 참이면 아무것도 하지 말고 돌아갑니다. `peek_latched_`를 보는 기존 조건은 그대로 두고, 그 옆에 나란히 둡니다.

```
peek_toggled_in_hold_이 참이면 → 즉시 반환한다 (로그도 남기지 않는다)
```

전환을 실제로 수행한 뒤에 참으로 만듭니다. 자리는 `peek_latched_ = true;` 바로 옆입니다.

`StopCornerWatch`에서 거짓으로 되돌리십시오. 곧 **Ctrl에서 손을 떼는 것이 유일한 재무장 조건**입니다.

### 이것이 바꾸는 동작

같은 Ctrl 유지 안에서는 되돌릴 수 없습니다. 바탕 화면을 보고 원래대로 돌아가려면 **Ctrl을 뗐다가 다시 누르고 코너를 짚어야** 합니다.

**이것은 의도된 변경입니다.** 지금은 커서가 코너 근처를 지나기만 해도 상태가 뒤집혀서 결과를 예측할 수 없습니다. 한 번의 동작에 한 번의 결과가 대응하는 편이 낫습니다.

---

## 5. 그대로 둘 것

- **재무장 구역(`kPeekRearmZoneDip`)과 걸쇠를 지우지 마십시오.** 4절이 들어가면 재무장 구역은 뜸 타이머가 헛도는 것을 줄이는 역할만 남지만, 지워서 얻을 것이 없습니다.
- **되살릴 창에 관한 규칙 전부를 그대로 두십시오.** 덮어쓰기 방지, 바탕 화면과 상단바 제외, 복귀 성공 뒤 비우기 모두 그대로입니다.
- 발동 조건(뜸 120밀리초, 감시 30밀리초, 코너 폭 14 DIP)을 건드리지 마십시오.
- **`[peek] toggle` 로그를 지우지 마십시오.** 이번 수정의 유일한 검증 근거입니다.
- `desktop_shown_`과 실제 화면이 어긋나는 문제는 이번에도 고치지 마십시오.
- `WM_MOUSELEAVE`와 탐침 `LogCtrlProbeIfChanged`도 그대로입니다.

## 6. 검증

1. Release 클린 빌드가 경고 없이 통과해야 합니다.
2. `peek_toggled_in_hold_`를 거짓으로 되돌리는 자리가 `StopCornerWatch` 하나뿐인지 확인하십시오. 걸쇠를 푸는 `StopDesktopPeek`에서 되돌리면 이번 수정이 무의미해집니다.
3. `StartDesktopPeek`의 이른 반환이 `[peek] toggle` 로그보다 **앞에** 있어야 합니다. 막힌 시도가 로그에 남으면 안 됩니다.
4. 나머지는 사용자 확인으로 넘기십시오. 판정 근거는 다음 둘입니다.
   - `watch on=1`과 `watch on=0` 사이에 `[peek] toggle` 줄이 **많아야 하나**다.
   - 최소화하고 Ctrl에서 손을 뗀 뒤 다시 Ctrl과 코너로 복귀했을 때, `restore hwnd`가 처음에 쓰던 창과 같다.

이 환경에서는 마우스와 키보드 입력을 합성할 수 없습니다. 사용자 화면에 입력을 밀어 넣으려고 하지 마십시오.

**빌드하려고 실행 중인 bamti를 종료했다면, 끝난 뒤 반드시 다시 띄워 놓으십시오.**

레지스트리에 쓰는 확인 절차는 넣지 마십시오.
