# 작업 지시서: 읽지 못한 설정 파일을 덮어쓰지 않는다

> 작업 당시의 진단과 지시를 남긴 기록입니다. 현재 코드의 설명이 아닙니다.

`TASK-BUILTIN-WIDGETS.md` 구현물의 검수에서 찾은 결함을 고치는 지시서입니다. 대상은 `src/settings.cpp`의 `SaveWidgetSettings` 하나이며, 잔여 검증 항목은 6절에 따로 적었습니다.

이 결함은 사용자에게 아무 신호 없이 일어납니다. 설정 파일이 사라진 뒤에야 알 수 있고, 그때는 이미 되돌릴 방법이 없습니다.

---

## 1. 결함

`SaveWidgetSettings`는 기존 파일을 읽어 모르는 키를 보존한 다음 새로 씁니다. 그런데 **읽기에 실패한 경우와 파일이 없는 경우를 구분하지 않습니다.** 그래서 읽지 못한 파일을 "보존할 내용이 없는 파일"로 취급하고 기본 문서로 덮어씁니다.

`src/settings.cpp:205` 부근입니다.

```cpp
bool too_large = false;
const std::string existing = ReadFileUtf8(path, &too_large);
// ...
const bool file_exists = GetFileAttributesW(path.c_str()) != INVALID_FILE_ATTRIBUTES;
bool parsed = false;
if (!too_large && !existing.empty()) {
  parsed = json::ParsePreserve(existing, &extra_topbar, &extra_root);
}
if (file_exists && !parsed && !too_large) {      // ← too_large이면 백업조차 하지 않는다
  BackupInvalidSettings(path);
  extra_topbar.clear();
  extra_root.clear();
}

const std::string text = FormatSettings(s, extra_topbar, extra_root);
if (!WriteFileUtf8Atomic(path, text)) {          // ← 그래도 쓴다
```

손실이 나는 경로는 두 가지입니다.

**경로 A. 64KB를 넘는 파일**

`ReadFileUtf8`은 크기가 상한을 넘으면 내용을 읽지 않고 `too_large`만 올린 채 빈 문자열을 돌려줍니다. 그러면 `parsed`는 거짓인데 `!too_large` 조건 때문에 백업 분기를 건너뛰고, 아래에서 파일을 기본 문서로 덮어씁니다. 사용자가 위젯 하나를 토글하는 순간 그 파일이 백업 없이 사라집니다.

**경로 B. 파일은 있지만 열지 못한 경우**

`ReadFileUtf8`은 파일이 없을 때와 `CreateFileW`가 실패했을 때를 똑같이 빈 문자열로 돌려줍니다. 편집기가 파일을 공유 거부로 열고 있거나, 백신이 잠깐 잠그거나, 권한이 막히면 읽기가 실패합니다. 이때는 `file_exists`가 참이고 `parsed`가 거짓이므로 **원본을 `.bak`으로 밀어내고 기본 문서를 새로 씁니다.** 백업이 남는다는 점에서 경로 A보다는 낫지만, 잠깐 잠긴 것뿐인 멀쩡한 설정이 초기화됩니다. 발생 확률은 이쪽이 더 높습니다.

두 경로의 공통 원인은 하나입니다. **읽지 못한 파일을 내용이 없는 파일과 같게 다룹니다.**

## 2. 고치는 방향

읽기 결과를 세 가지가 아니라 네 가지로 구분하고, 그 가운데 **내용을 확인한 경우에만** 파일을 씁니다. 확인하지 못한 파일은 건드리지 않는 것이 언제나 옳습니다.

`ReadFileUtf8`의 서명을 바꿉니다.

```cpp
enum class SettingsRead { kOk, kMissing, kTooLarge, kFailed };

SettingsRead ReadFileUtf8(const std::wstring& path, std::string* out);
```

- `kMissing`: `CreateFileW`가 `ERROR_FILE_NOT_FOUND` 또는 `ERROR_PATH_NOT_FOUND`로 실패했습니다.
- `kFailed`: 그 밖의 이유로 열지 못했거나, `GetFileSizeEx`나 `ReadFile`이 실패했습니다.
- `kTooLarge`: 크기가 64KB를 넘습니다.
- `kOk`: 내용을 읽었습니다. 빈 파일도 여기에 들어갑니다.

`SaveWidgetSettings`의 처리는 다음 표대로 합니다.

| 읽기 결과 | 파싱 | 처리 |
|---|---|---|
| `kMissing` | 해당 없음 | 보존할 것이 없으므로 새 문서를 씁니다. |
| `kOk` | 성공 | 원문 조각을 보존해 씁니다. 지금 동작 그대로입니다. |
| `kOk` | 실패 | `.bak`으로 옮기고 새 문서를 씁니다. 지금 동작 그대로입니다. |
| `kTooLarge` | 해당 없음 | **쓰지 않고 `false`를 반환합니다.** 로그를 남깁니다. |
| `kFailed` | 해당 없음 | **쓰지 않고 `false`를 반환합니다.** 로그를 남깁니다. |

`GetFileAttributesW`로 존재를 다시 확인하는 `file_exists` 변수는 지웁니다. `kMissing`이 그 역할을 하며, 읽은 시점과 확인하는 시점이 어긋날 여지도 함께 없어집니다.

빈 파일(`kOk`이고 내용이 0바이트)은 `ParsePreserve`가 실패로 돌려줄 것입니다. 그러면 `.bak` 분기를 타는데, 0바이트짜리를 굳이 백업할 필요는 없습니다. **내용이 비어 있으면 백업하지 말고 바로 새 문서를 쓰도록** 조건을 하나 더 두십시오.

`LoadWidgetSettings`도 같은 열거형을 쓰도록 맞춥니다. `kTooLarge`일 때 지금처럼 한 번만 로그를 남기고, `kFailed`일 때도 한 번만 로그를 남깁니다. 반환값은 지금과 같이 기본값입니다.

## 3. 저장 실패를 사용자에게 어떻게 알리는가

알리지 않습니다. 지금 구조에서 `SetSettings`는 메모리의 설정을 먼저 바꾸고 저장을 스레드 풀에 넘기므로, 저장이 실패해도 위젯은 켜지고 꺼집니다. 다음 실행에서 예전 값으로 돌아갈 뿐입니다.

여기에 대화 상자나 상단바 경고를 새로 만들지 마십시오. 로그 한 줄로 충분합니다. 7단계에서 설정 화면을 만들 때 다시 다룰 문제이며, 지금 임시 알림 경로를 만들면 그때 걷어내야 합니다.

---

## 4. 하지 말아야 할 것

1. `kSettingsMaxBytes` 상한을 올려서 경로 A를 피하지 마십시오. 상한은 방어선이고, 문제는 상한이 아니라 상한에 걸린 뒤의 처리입니다.
2. 읽기 실패를 재시도하는 반복문을 넣지 마십시오. 저장은 사용자가 메뉴를 누를 때만 일어나므로 다음 조작이 곧 재시도입니다.
3. `SaveWidgetSettings`의 다른 동작을 함께 손보지 마십시오. 원자적 쓰기와 원문 보존은 그대로 둡니다.
4. `settings.hpp`의 공개 인터페이스를 바꾸지 마십시오. 고치는 범위는 `settings.cpp` 내부입니다.

## 5. 검증

**빌드**
- [ ] `/W4` 경고 없이 Debug와 Release가 빌드됩니다.

**경로 A**
- [ ] `settings.json`을 65KB 이상으로 만든 뒤 메뉴에서 위젯을 토글하면, 파일이 **바이트 단위로 그대로**이고 `.bak`이 생기지 않으며 로그에 한 줄이 남습니다.

**경로 B**
- [ ] 정상 `settings.json`을 다른 프로세스가 공유 거부로 연 상태에서 토글하면, 파일이 그대로이고 `.bak`이 생기지 않으며 로그에 한 줄이 남습니다. 잠그는 방법은 다음과 같습니다.

  ```powershell
  $f = [System.IO.File]::Open("$env:USERPROFILE\.bamti\settings.json", 'Open', 'Read', 'None')
  # 여기서 상단바 우클릭 메뉴로 위젯을 토글한 뒤
  $f.Close()
  ```

**회귀**
- [ ] 파일이 없는 상태에서 토글하면 새로 만들어집니다.
- [ ] 깨진 JSON을 넣고 토글하면 `.bak`이 생기고 정상 문서가 새로 써집니다.
- [ ] 0바이트 파일에서 토글하면 `.bak` 없이 정상 문서가 써집니다.
- [ ] `keep_me` 같은 모르는 키를 넣어 두고 토글해도 그 키가 남습니다.
- [ ] 토글한 값이 다시 실행해도 유지됩니다.
