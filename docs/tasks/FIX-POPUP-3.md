# 작업 지시서 4: 메뉴가 열자마자 닫히고 다시 열리기를 반복하는 문제

> 작업 당시의 진단과 지시를 남긴 기록입니다. 현재 코드의 설명이 아닙니다.

커밋 `f291dfd` 이후 우클릭 한 번에 메뉴가 **열두 번 열리고 닫힙니다.** 이 폭주가 지연과 멈춤의 직접 원인입니다.

---

## 1. 증거

우클릭 **한 번**에 대한 로그입니다. 시각을 보십시오. 44밀리초입니다.

```
09:27:09.524 [dock]  menu open index=0 name=explorer.exe
09:27:09.530 [popup] open rows=7 shown 0ms
09:27:09.530 [popup] msg=rbuttondown pt=27,260 inside=0
09:27:09.530 [popup] dismiss reason=outside-click index=-1
09:27:09.531 [dock]  menu open index=0 name=explorer.exe      ← 다시 열림
09:27:09.534 [popup] msg=rbuttondown pt=12,258 inside=0
09:27:09.534 [popup] dismiss reason=outside-click index=-1
09:27:09.535 [dock]  menu open index=0 name=explorer.exe      ← 또 열림
   ... 같은 순환이 09:27:09.568까지 열두 번 반복 ...
```

`alive tick=20`이 09:27:10.817에 남았으므로 이 시점까지 UI 스레드는 살아 있었습니다. 그러나 09:27:11.606 이후 `alive` 줄이 끊깁니다. `tick=40`이 나와야 할 09:27:12.8 무렵에 아무것도 없습니다. **그 사이에 UI 스레드가 멈췄습니다.**

## 2. 순환의 구조

```
1. 사용자가 독 아이콘을 우클릭한다.
2. 독의 WM_RBUTTONUP이 메뉴를 연다. 팝업이 SetCapture를 잡는다.
3. 팝업에 WM_RBUTTONDOWN이 도착한다. 커서는 팝업 밖이다(inside=0).
4. 팝업이 outside-click으로 판정해 닫는다. ReleaseCapture를 부른다.
5. 캡처가 풀리면서 버튼 메시지가 독으로 간다.
6. 독의 WM_RBUTTONUP이 다시 메뉴를 연다.  → 2번으로 돌아간다.
```

사람이 44밀리초에 열두 번 클릭할 수는 없습니다. 3번의 `WM_RBUTTONDOWN`은 사용자가 새로 누른 것이 아니라, **메뉴를 연 그 클릭이 캡처 전환 과정에서 다시 배달된 것**입니다.

## 3. 왜 지금 터졌는가

지난 지시서 2-5에서 팝업을 커서로부터 4dip 띄웠습니다. 그 전에는 커서가 팝업 경계에 걸쳐 `inside` 판정이 들쭉날쭉했고, 우연히 `inside=1`이 나오면 순환이 끊겼습니다.

이제는 커서가 **항상 팝업 밖**입니다. 로그의 `inside=0`이 예외 없이 그렇습니다. 그래서 순환이 매번 성립합니다.

**2-5를 되돌리지 마십시오.** 간격 자체는 옳은 수정이고, 이 결함을 가리고 있던 우연을 걷어내 드러냈을 뿐입니다. 원래 있던 버그입니다.

## 4. 수정 지시

### 4-1. 팝업을 연 클릭이 팝업을 닫지 않게 한다 (필수, 이것이 핵심)

팝업은 **버튼이 한 번 떼어진 것을 확인한 뒤에만** 바깥 클릭을 받아들여야 합니다. 열릴 당시 진행 중이던 클릭은 무시해야 합니다.

`src/popup_surface.hpp`에 멤버를 추가하십시오.

```cpp
bool armed_ = false;   // 버튼이 모두 떼어진 것을 본 뒤에야 참이 된다
```

동작 규칙입니다.

1. `Open()`에서 `armed_ = false`로 둡니다.
2. `OnGuardTimer()`에서 모든 마우스 버튼이 떼어진 상태(`!mouse`)를 관측하면 `armed_ = true`로 바꿉니다. 한 번 참이 되면 그 팝업이 닫힐 때까지 유지합니다.
3. **`armed_`가 거짓인 동안에는 바깥 클릭으로 닫지 않습니다.** 다음 두 곳 모두에 적용하십시오.
   - `Handle()`의 `WM_LBUTTONDOWN` / `WM_RBUTTONDOWN` / `WM_MBUTTONDOWN` 분기
   - `OnGuardTimer()`의 `kOutsidePoll` 분기
4. 안쪽 클릭 실행(`kInvoke`)에도 같은 조건을 적용하십시오. `armed_`가 거짓이면 실행하지 않습니다. 메뉴를 연 클릭이 그대로 항목을 실행해 버리는 것을 막습니다.

가드 타이머가 50ms 주기이므로, 사용자가 버튼을 떼면 늦어도 50ms 안에 `armed_`가 참이 됩니다. 체감되지 않습니다.

`armed_`를 시간 기반(예: "열린 뒤 150ms 동안 무시")으로 만들지 마십시오. 사용자가 버튼을 오래 누르고 있으면 그 사이에 무장이 풀려 같은 순환이 재발합니다. **반드시 버튼이 떼어진 것을 관측하는 방식으로 구현하십시오.**

### 4-2. 순환을 감지하면 로그를 남긴다 (필수)

같은 결함이 다른 경로로 재발할 수 있습니다. `Dock::OpenDockMenu()`에 직전 열림 시각을 기록하고, **100ms 안에 다시 열리면** 경고를 남기십시오.

```cpp
Log(L"dock", L"menu reopen storm %ums since last", /* 경과 시간 */);
```

로그만 남기고 동작은 막지 마십시오. 정상적인 빠른 조작을 막으면 안 됩니다. 이 줄이 다음 재현에서 순환을 즉시 알려 줍니다.

### 4-3. Spotlight 입력 지연을 계측한다 (필수, 조사만)

사용자가 다음 증상을 보고했습니다.

> spotlight 팝업은 됐는데 검색하려고 텍스트 입력하니까 포인터가 로딩모양으로 바뀌더니 멈췄어

포인터가 대기 모양으로 바뀌는 것은 **UI 스레드가 오래 반환하지 않는다**는 신호입니다. Spotlight 검색이 UI 스레드에서 동기로 파일이나 인덱스를 훑고 있을 가능성이 높습니다.

`src/spotlight.cpp`에는 **사용자의 미커밋 수정이 있습니다.** 그 내용을 덮어쓰거나 되돌리지 마십시오. 이번에는 **고치지 말고 계측만** 하십시오.

- 검색어가 바뀌어 결과를 다시 만드는 함수의 시작과 끝에 `GetTickCount64()`를 찍고, **50ms를 넘을 때만** 다음을 남기십시오.

  ```cpp
  Log(L"spotlight", L"query len=%zu results=%zu %ums", /* 질의 길이 */, /* 결과 수 */, /* 소요 */);
  ```
- 그 함수 안에서 디스크를 훑거나 COM을 호출하는 지점이 있으면, **위치만 보고**에 적으십시오. 수정하지 마십시오.

4-1을 적용한 뒤에도 Spotlight가 멈추면 이 로그가 원인을 가리킵니다. 별도 지시서로 다루겠습니다.

## 5. 하지 말아야 할 것

- 2-5의 4dip 간격을 되돌리지 마십시오. 3장에 이유를 적었습니다.
- `UpdateWindow()` 수정, 폴링 입력 처리, 지문 기반 `Rebuild` 생략을 되돌리지 마십시오. 모두 효과가 확인되었습니다.
- `armed_`를 시간 기반으로 구현하지 마십시오. 4-1에 이유를 적었습니다.
- 4-2에서 순환을 **차단**하지 마십시오. 로그만 남깁니다. 원인을 고치지 않고 증상을 막으면 다음에 다른 모습으로 돌아옵니다.
- `src/spotlight.cpp`와 `src/spotlight.hpp`의 미커밋 수정을 덮어쓰지 마십시오. 4-3은 계측 추가만 허용합니다.
- `WH_MOUSE_LL`, `WH_KEYBOARD_LL`을 새로 도입하지 마십시오.
- `SetForegroundWindow`, `AttachThreadInput`을 도입하지 마십시오.
- `WS_EX_NOACTIVATE`를 떼지 마십시오.

## 6. 검증

**순환 (핵심)**
- [ ] 우클릭 한 번에 `[dock] menu open`이 **정확히 한 줄만** 남는다. 이것이 이번 수정의 판정 기준이다.
- [ ] `[dock] menu reopen storm` 줄이 남지 않는다.
- [ ] 메뉴가 뜨는 순간 깜빡임이 없다.

**조작**
- [ ] 메뉴를 **열 번 연속** 열고 닫아도 멈추지 않는다.
- [ ] 메뉴를 연 뒤 커서를 가만히 두어도 저절로 닫히지 않는다.
- [ ] 항목을 클릭하면 실행되고 `[dock] menu cmd=`가 남는다.
- [ ] 우클릭으로 메뉴를 연 직후, 버튼을 떼자마자 바깥을 클릭하면 정상으로 닫힌다. `armed_`가 제때 무장되는지 확인하는 항목이다.
- [ ] 버튼을 3초간 누르고 있다가 떼어도 메뉴가 남아 있다. 시간 기반이 아님을 확인하는 항목이다.
- [ ] 메뉴가 열린 상태에서 다른 아이콘을 우클릭하면, 첫 클릭은 닫기만 하고 두 번째 클릭에서 새 메뉴가 열린다.

**Spotlight**
- [ ] 검색어를 입력할 때 `[spotlight] query ... %ums` 줄이 남는지 확인하고 수치를 보고한다.
- [ ] 디스크나 COM을 훑는 지점을 찾았으면 파일과 함수 이름을 보고한다.

**회귀**
- [ ] `[popup] open ... shown` 값이 16ms 이하를 유지한다.
- [ ] 유휴 60초 누적 CPU가 이전 측정(3.8초)보다 나빠지지 않는다.
- [ ] Release 빌드가 `/W4` 경고 없이 통과한다.
