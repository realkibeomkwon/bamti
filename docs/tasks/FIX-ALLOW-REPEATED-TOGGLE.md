# 작업 지시서: 한 번 누르고 있는 동안에도 자유롭게 전환하게 되돌린다

> 작업 당시의 진단과 지시를 남긴 기록입니다. 현재 코드의 설명이 아닙니다.

`FIX-ONE-TOGGLE-PER-HOLD.md`(커밋 `98c82ab`)를 되돌립니다. 건드리는 파일은 `src/menu_bar.cpp`와 `src/menu_bar.hpp`입니다.

---

## 1. 요구사항을 잘못 잡았다

`98c82ab`은 한 번의 Ctrl 유지에 전환을 한 번으로 제한했습니다. **이 제약이 사용자가 원하는 동작과 정면으로 어긋납니다.**

사용자가 원하는 흐름은 다음과 같습니다.

```
Ctrl을 누른다
창이나 파일을 끌기 시작한다
코너를 짚는다        → 바탕 화면이 보인다
화면 가운데로 옮겨 놓는다
다시 코너를 짚는다    → 원래 창들이 돌아온다
Ctrl에서 손을 뗀다
```

**Ctrl은 처음부터 끝까지 눌린 채로 있어야 합니다.** 전환할 때마다 Ctrl을 다시 누르게 만들면 끌고 있던 것을 놓치게 되므로 드래그 앤 드롭이 성립하지 않습니다.

지난 지시서는 반복 전환 자체를 결함으로 보았지만, 반복 전환은 **원래 있어야 하는 기능**이었습니다. 문제는 전환이 반복되는 것이 아니라 사용자가 의도하지 않은 순간에도 전환되는 것입니다.

## 2. 되돌릴 것

`peek_toggled_in_hold_`를 **완전히 제거하십시오.** 자리는 네 곳입니다.

- `src/menu_bar.hpp`의 멤버 선언
- `StartDesktopPeek`의 이른 반환 조건에서 뺍니다. `if (peek_latched_) { return; }`로 되돌립니다.
- `StartDesktopPeek` 끝의 `peek_toggled_in_hold_ = true;`
- `StopCornerWatch`의 `peek_toggled_in_hold_ = false;`

`git revert 98c82ab`로 처리해도 됩니다. 다만 되돌린 뒤에 3절의 항목이 그대로 남아 있는지 반드시 확인하십시오.

## 3. 그대로 둘 것

- **재무장 구역(`kPeekRearmZoneDip`, 96 DIP)을 지우지 마십시오.** 이것은 사용자의 의도한 왕복을 막지 않습니다. 코너에서 화면 가운데까지 갔다가 돌아오는 동작은 96 DIP을 훨씬 넘으므로 정상으로 다시 전환됩니다. 코너 근처의 작은 흔들림만 걸러 냅니다.
- **되살릴 창에 관한 규칙 전부를 그대로 두십시오.** 덮어쓰기 방지, 바탕 화면과 상단바 제외, 복귀 성공 뒤 비우기 모두 유지합니다.
- 발동 조건(뜸 120밀리초, 감시 30밀리초, 코너 폭 14 DIP)을 건드리지 마십시오.
- **`[peek] toggle` 로그를 지우지 마십시오.** 다음 관측의 근거입니다.
- `desktop_shown_` 동기화 문제와 탐침 `LogCtrlProbeIfChanged`도 그대로입니다.

## 4. 검증

1. Release 클린 빌드가 경고 없이 통과해야 합니다.
2. `peek_toggled_in_hold_`라는 이름이 저장소 어디에도 남아 있지 않아야 합니다.
3. `kPeekRearmZoneDip`을 쓰는 해제 판정이 그대로 있어야 합니다.
4. `StartDesktopPeek`의 `[peek] toggle` 로그가 그대로 있어야 합니다.
5. 나머지는 사용자 확인으로 넘기십시오. 판정 근거는 다음 하나입니다.
   - **Ctrl을 누른 채로** 코너와 화면 가운데를 오가면 오갈 때마다 전환된다.

이 환경에서는 마우스와 키보드 입력을 합성할 수 없습니다. 사용자 화면에 입력을 밀어 넣으려고 하지 마십시오.

**빌드하려고 실행 중인 bamti를 종료했다면, 끝난 뒤 반드시 다시 띄워 놓으십시오.**

레지스트리에 쓰는 확인 절차는 넣지 마십시오.
