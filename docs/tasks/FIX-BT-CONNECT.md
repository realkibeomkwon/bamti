# FIX-BT-CONNECT — 해제한 블루투스 장치를 다시 연결하지 못하는 것을 고친다

이 문서는 2026-09-05 시점의 작업 지시서이며, 현재 코드의 설명이 아니라 당시의 기록이다.

## 증상

`TASK-BT-CONNECT.md`로 구현한 연결 기능을 실기에서 확인하다가 나왔다. 짝지어진 AirPods를 눌러 연결을 끊는 데 성공했으나, 다시 누르자 연결되지 않고 Windows 설정 앱이 열렸다.

## 원인

로그가 그대로 보여 준다.

```
21:14:42 [bt] set service state 기범의 AirPods Pro connect=0 ok=8/8 took 27091 ms
21:14:47 [bt] set service state 기범의 AirPods Pro connect=1 ok=0/0 took 0 ms
21:14:51 [bt] set service state 기범의 AirPods Pro connect=1 ok=0/0 took 1 ms
```

두 가지가 드러난다.

**첫째, `BLUETOOTH_SERVICE_DISABLE`은 서비스를 끄는 것이 아니라 제거한다.** 해제할 때 8개를 모두 성공적으로 처리했는데(`ok=8/8`), 그 뒤 재연결에서는 열거 결과가 아예 0개다(`ok=0/0`). `BluetoothEnumerateInstalledServices`가 "설치된" 서비스를 돌려주는 함수이므로, 제거하고 나면 켤 대상이 남지 않는다. `SetBtDeviceConnected`는 서비스가 0개이면 거짓을 돌려주고, 패널은 그 실패를 받아 설정 앱을 연다.

`TASK-BT-CONNECT.md`를 쓸 때 이 성질을 놓쳤다. 켜고 끄는 대칭 연산이라고 본 것이 잘못이었다.

**둘째, 해제가 27초 걸렸다.** 8개 서비스를 하나씩 처리하며 각각 3초 넘게 쓴 셈이다. 화면에는 "연결 끊는 중…"이 계속 떠 있었으므로 멈춘 것처럼 보이지는 않았겠지만, 너무 길다.

---

## 1. 끄기 전에 서비스 목록을 기억한다

해제할 때 열거한 GUID를 장치 주소별로 남겨 두었다가, 다시 연결할 때 그것을 쓴다.

`src/bt_devices.hpp`의 시그니처를 바꾼다.

```cpp
// connect가 거짓이면 지금 설치된 서비스를 끄고, 껐던 GUID를 services에 담아 돌려준다.
// connect가 참이면 services에 담긴 GUID를 켠다. 비어 있으면 설치된 것을 열거해 쓰고,
// 그것마저 없으면 장치 종류에 맞는 표준 서비스를 시도한다.
// 몇 초가 걸릴 수 있으므로 UI 스레드에서 부르면 안 된다.
bool SetBtDeviceConnected(const BLUETOOTH_DEVICE_INFO& info, bool connect, std::vector<GUID>* services);
```

`BuiltinWidgets`가 주소를 열쇠로 그 목록을 들고 있는다.

```cpp
std::map<std::wstring, std::vector<GUID>> bt_disabled_services_;
```

- 해제에 성공하면 껐던 GUID를 이 표에 넣는다.
- 연결에 성공하면 그 항목을 지운다.
- 앱이 다시 시작하면 표가 비는데, 그때는 아래 2절의 대비책이 받는다. 설정 파일에까지 저장할 필요는 없다.

## 2. 표가 비었을 때의 대비책

앱을 다시 켠 뒤에 연결하려 하거나, 사용자가 Windows 설정에서 해제한 장치를 우리 패널에서 연결하려 하면 표가 비어 있다. 이때는 **장치 종류를 보고 표준 서비스 GUID를 시도한다.**

`bthdef.h`에 정의된 값을 쓴다. 직접 적어 넣지 말고 헤더의 상수를 쓰되, 없으면 아래 값을 확인한 뒤 상수로 둔다.

| 서비스 | UUID |
| --- | --- |
| A2DP Sink | `0000110B-0000-1000-8000-00805F9B34FB` |
| Handsfree | `0000111E-0000-1000-8000-00805F9B34FB` |
| Headset | `00001108-0000-1000-8000-00805F9B34FB` |
| AV Remote Control | `0000110E-0000-1000-8000-00805F9B34FB` |
| HID | `00001124-0000-1000-8000-00805F9B34FB` |

`BLUETOOTH_DEVICE_INFO::ulClassofDevice`의 주 장치 클래스를 보고 고른다. 이미 `BtClassGlyph`가 같은 값을 읽어 아이콘을 고르고 있으니 그 판정을 참고하라.

- 오디오(주 클래스 0x04)이면 A2DP Sink, Handsfree, Headset, AV Remote Control을 시도한다.
- 주변기기(주 클래스 0x05)이면 HID를 시도한다.
- 그 밖이면 시도하지 않고 거짓을 돌려준다. 설정 앱으로 물러선다.

**하나라도 `ERROR_SUCCESS`이면 참**이라는 지금 판정은 그대로 둔다.

## 3. 처리할 서비스를 줄여 시간을 아낀다

27초는 너무 길다. 8개를 전부 건드릴 필요가 없다.

**로그에 GUID를 남기는 것부터 하라.** 지금은 개수만 남아서 8개가 무엇이었는지 알 수 없다.

```cpp
Log(L"bt", L"service %d/%d {%08lX-...} state=%lu took %.0f ms", i + 1, n, ..., err, ms);
```

한 줄에 하나씩, 각 호출에 걸린 시간과 결과를 남긴다. 무엇이 오래 걸리는지 보이면 다음 판단을 할 수 있다.

그 뒤 **오디오 장치라면 위 표의 네 가지에 해당하는 서비스만 처리한다.** 열거 결과에서 그 GUID만 골라 쓰고 나머지는 건너뛴다. 주변기기는 HID만 쓴다. 어느 쪽에도 해당하지 않는 종류는 지금처럼 전부 처리한다.

이렇게 줄여도 시간이 크게 줄지 않으면, 그 사실을 로그와 함께 보고하라. 그때는 다른 방향을 잡는다.

## 4. 진행 중 표시

27초가 걸릴 수 있으므로 "연결 끊는 중…"이 오래 떠 있는다. 지금 구조로 화면이 멈추지는 않으니 그대로 두어도 된다. 다만 **요청이 시작된 뒤 60초가 지나면 진행 중 표시를 스스로 거둔다.** 워커가 어떤 이유로 응답하지 않아도 행이 영원히 "연결 중…"으로 남지 않게 하려는 것이다.

cmake --build out/cmake-debug --config Debug

경고 없이 통과해야 한다.

### 하지 말 것

- **연결과 해제를 반복해서 시험하지 마라.** 사용자가 쓰는 오디오 장치다. 이번 문제도 한 번의 해제로 생겼다.
- **앱을 `taskkill` 로 강제 종료하지 마라.** 빌드에서 `LNK1168` 이 나면 종료를 요청하라.
- **짝짓기를 해제하지 마라.** `BluetoothRemoveDevice` 는 쓰지 않는다.
- 검색(`bt_scan`)과 트레이 아이콘 필터는 확인이 끝났으니 건드리지 마라.

### 보고할 것

- 서비스별 GUID와 걸린 시간이 로그에 남는지
- 오디오 장치에서 처리 대상을 줄였을 때 몇 개가 남는지
- 표가 비었을 때의 대비책이 어느 경로로 도는지
