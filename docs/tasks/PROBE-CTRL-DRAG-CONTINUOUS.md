# 작업 지시서: 드래그가 진행되는 동안에는 탐침을 매 틱 남긴다

> 작업 당시의 진단과 지시를 남긴 기록입니다. 현재 코드의 설명이 아닙니다.

`PROBE-CTRL-DURING-DRAG.md`(커밋 `73af1ad`)의 후속입니다. **이번에도 탐침만 손봅니다. 동작을 고치지 마십시오.**

건드리는 파일은 `src/menu_bar.cpp`입니다.

---

## 1. 지난 탐침으로 확정한 것

**드래그 도중에도 저수준 키보드 훅은 살아 있습니다.**

Ctrl을 먼저 누르고 드래그한 구간(성공하는 경우)의 기록입니다.

```
13:23:53.337 probe hook=34  async_c=1 async_l=1 lbtn=1 capture=00000000007A0E30
13:24:01.068 probe hook=145 async_c=1 async_l=1 lbtn=1 capture=0000000000000000
```

7.7초 동안 `hook`이 34에서 145로 올랐습니다. 초당 열네 건꼴이고, Ctrl을 누르고 있을 때의 자동 반복과 일치합니다. **버튼이 눌린 채(`lbtn=1`)로도 훅에 키 이벤트가 계속 들어왔습니다.**

그러므로 "드래그 중에는 훅이 죽는다"는 가설은 **틀렸습니다.**

## 2. 왜 아직 판정하지 못하는가

지금 탐침은 **직전 값과 달라졌을 때만** 한 줄 남깁니다. 로그가 자라지 않게 하려고 그렇게 만들었고 그 목적은 달성했습니다.

그런데 실패하는 경우는 **아무 값도 바뀌지 않는 상태**입니다. 드래그가 시작되면서 `lbtn`이 0에서 1로 바뀔 때 한 줄이 남고, 그 뒤로 Ctrl이 보이지 않으면 `async_c`도 `hook`도 그대로이므로 **더 이상 아무 줄도 남지 않습니다.**

곧 지금 구조로는 "값이 안 변했다"와 "우리가 눈이 멀었다"를 구분할 수 없습니다.

---

## 3. 고칠 것

### 3-1. 드래그로 보이는 동안에는 매 틱 남긴다

`LogCtrlProbeIfChanged`의 판정을 이렇게 바꾸십시오.

```
lbtn이 1이면 → 변화 여부와 상관없이 남긴다
lbtn이 0이면 → 지금처럼 변했을 때만 남긴다
```

버튼을 누르고 있는 시간은 짧고 드문 일이므로 로그가 폭주하지 않습니다. 200밀리초 주기이므로 10초짜리 드래그가 쉰 줄입니다.

**이것이 이 지시서의 핵심입니다.** 드래그 내내 끊기지 않는 기록이 남아야 Ctrl을 누른 순간에 무엇이 바뀌는지(또는 아무것도 안 바뀌는지) 볼 수 있습니다.

### 3-2. 훅이 마지막으로 본 키를 함께 남긴다

훅 안에 전역 둘을 더하십시오. **로그는 절대 부르지 마십시오. 대입만 합니다.**

```cpp
volatile DWORD g_hook_last_vk = 0;
volatile UINT g_hook_last_msg = 0;
```

계수기를 올리는 자리 바로 옆에서 `info->vkCode`와 `wparam`을 담습니다.

탐침 줄에 두 값을 더합니다.

```
[peek] probe hook=%u lastvk=%lu lastmsg=0x%08x async_c=%d ... (이하 기존과 같음)
```

이 둘은 **변화 비교 대상에 넣으십시오.** `lbtn=0`일 때 값이 바뀌면 한 줄 남는 것이 맞습니다.

### 3-3. 이것으로 무엇이 갈리는가

사용자가 "드래그 시작 → Ctrl 누름 → 코너"를 한 번 하면 드래그 내내 줄이 남고, 그중 Ctrl을 누른 시점에서 다음이 갈립니다.

1. **`hook`이 오르고 `lastvk=162`(또는 163)로 바뀐다** → 훅은 Ctrl을 봤습니다. 그런데 `watch msg`가 없다면 `g_ctrl_held`가 굳어 전이가 생기지 않은 것이고, 원인이 확정됩니다.
2. **`hook`은 오르는데 `lastvk`가 Ctrl이 아니다** → 다른 키만 들어오고 Ctrl은 누군가 먼저 가로챈 것입니다.
3. **`hook`이 전혀 오르지 않는다** → 그 순간에만 훅이 건너뛰어집니다. 1절과 모순되므로 조건을 더 좁혀야 합니다.
4. **`hook`은 오르고 `lastvk`도 Ctrl인데 `async_c`가 계속 0이다** → 훅은 보는데 키 상태 API가 못 보는 것입니다. 이 경우 예비 감시를 `GetAsyncKeyState` 대신 훅이 채운 값으로 판정하도록 바꾸면 됩니다.

**어느 갈래든 다음 수가 분명해집니다.**

---

## 4. 하지 말 것

- 동작을 바꾸지 마십시오. 걸쇠, 뜸, 감시 주기, 코너 폭, 예비 감시 주기 전부 그대로입니다.
- **훅 안에서 로그를 부르지 마십시오.** 대입 두 줄만 더합니다.
- Raw Input, `WH_MOUSE_LL`, `AttachThreadInput` 모두 이번 범위가 아닙니다.
- `lbtn=1`일 때 남기는 주기를 200밀리초보다 짧게 하지 마십시오.

---

## 5. 검증

1. Release 클린 빌드가 경고 없이 통과해야 합니다.
2. 버튼을 누르지 않은 채 가만히 두면 로그가 자라지 않아야 합니다.
3. 마우스 왼쪽 버튼을 몇 초 누르고 있으면 200밀리초마다 한 줄씩 남아야 합니다.
4. `LowLevelKeyboardProc` 안에 `Log` 호출이 없어야 합니다.
5. 드래그 도중 관측은 사용자 확인으로 넘기십시오.

이 환경에서는 마우스와 키보드 입력을 합성할 수 없습니다. 사용자 화면에 입력을 밀어 넣으려고 하지 마십시오.

**빌드하려고 실행 중인 bamti를 종료했다면, 끝난 뒤 반드시 다시 띄워 놓으십시오.**

레지스트리에 쓰는 확인 절차는 넣지 마십시오.
