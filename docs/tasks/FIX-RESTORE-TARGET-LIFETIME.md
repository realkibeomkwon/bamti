# 작업 지시서: 되살릴 창을 Ctrl에서 손을 떼도 잊지 않게 한다

> 작업 당시의 진단과 지시를 남긴 기록입니다. 현재 코드의 설명이 아닙니다.

`FIX-PEEK-TOGGLE-FLAPPING.md`(커밋 `ee4884b`)의 후속입니다. 건드리는 파일은 `src/menu_bar.cpp`입니다.

**앞 지시서의 4-2절에서 지시가 틀렸습니다. 그 부분만 되돌립니다. 나머지는 전부 그대로 둡니다.**

---

## 1. 무엇이 잘못되었는가

앞 지시서는 되살릴 창(`restore_target_`)을 `StopCornerWatch`에서 비우라고 했습니다. 곧 수명을 "Ctrl을 누르고 있는 한 번의 구간"으로 잡았습니다. **이 판단이 틀렸습니다.** 가장 흔한 사용 흐름이 그대로 깨집니다.

```
Ctrl을 누른다 → 코너 → 최소화된다 (되살릴 창으로 작업 창을 기억)
Ctrl에서 손을 뗀다                  ← 여기서 기억이 지워진다
바탕 화면을 본다
다시 Ctrl을 누른다 → 코너 → 복귀    ← 되살릴 창이 없어 복귀를 건너뛴다
```

마지막 줄에서 `restore_target_`이 `nullptr`이므로 `SetForegroundWindow` 호출이 통째로 건너뛰어지고, 어느 창이 맨 앞에 오는지는 다시 셸이 정합니다. 이것은 커밋 `4212d20`이 넣은 기능을 무력화하는 것이고, 사용자가 애초에 보고한 "엉뚱한 창이 맨 앞에 온다"는 증상으로 되돌아가는 길입니다.

## 2. 왜 원래 수명이 맞는가

되살릴 창이 오염된 원인은 수명이 아니라 **반복 전환**이었습니다. 복귀가 끝나기 전에 다음 최소화가 일어나서, 셸이 임시로 앞에 올려놓은 창을 기억해 버린 것입니다. 그 반복 전환은 재무장 구역(`kPeekRearmZoneDip`)으로 이미 막았습니다.

반복 전환이 사라지면 원래 수명이 스스로 맞아 들어갑니다. 복귀에 성공하면 되살린 창이 전경이 되므로, 그 뒤에 다시 최소화할 때 같은 창을 다시 잡습니다.

**되살릴 창의 수명은 "최소화한 순간부터 복귀가 끝날 때까지"입니다. Ctrl과는 상관이 없습니다.**

---

## 3. 고칠 것

### 3-1. `StopCornerWatch`에서 비우지 않는다

`StopCornerWatch`에 앞 지시서로 넣은 다음 한 줄을 **지우십시오.**

```cpp
restore_target_ = nullptr;
```

같은 함수의 다른 줄(`corner_watch_on_`, `last_corner_hit_`, `peek_dwell_armed_`, `StopDesktopPeek`)은 그대로 둡니다.

### 3-2. 복귀에 성공한 뒤에 비운다

`kDesktopIconicTimerId` 처리에서, 복귀 성공 갈래가 끝나는 자리에 비우는 코드를 되살리십시오. 위치는 다음과 같습니다.

```
if (desktop_pending_undo_ && desktop_hr_ == S_OK) {
    if (restore_target_ != nullptr && IsWindow(...) && !IsIconic(...)) {
        ... SetWindowPos, SetForegroundWindow, 로그 ...
    }
    restore_target_ = nullptr;   ← 여기에 되살린다
}
```

**안쪽 `if`가 아니라 바깥쪽 `if` 안에 두십시오.** 되살릴 창이 이미 닫혔거나 아직 최소화 상태여서 안쪽 갈래로 들어가지 못한 경우에도, 복귀 자체가 성공했다면 그 기억은 수명을 다한 것입니다. 남겨 두면 다음 주기에 낡은 창을 올립니다.

---

## 4. 그대로 둘 것

- **재무장 구역**(`kPeekRearmZoneDip`, 96 DIP)과 해제 판정을 건드리지 마십시오. 이번 수정의 전제입니다.
- **되살릴 창을 덮어쓰지 않는 규칙**과 **바탕 화면(`Progman`, `WorkerW`)과 상단바를 대상에서 빼는 규칙**은 옳습니다. 그대로 둡니다.
- `WM_MOUSELEAVE`에서 `StopDesktopPeek`을 지운 것도 그대로 둡니다. 커서가 상단바 아래로 내려가는 것만으로 걸쇠가 풀리면 재무장 구역이 무의미해지므로, 같은 취지의 변경입니다.
- `[peek] toggle` 로그, 뜸 120밀리초, 감시 주기 30밀리초, 코너 폭 14 DIP, 탐침 `LogCtrlProbeIfChanged` 모두 그대로입니다.
- `desktop_shown_`과 실제 화면이 어긋나는 문제는 이번에도 고치지 마십시오. 기록만 모읍니다.

---

## 5. 검증

1. Release 클린 빌드가 경고 없이 통과해야 합니다.
2. `StopCornerWatch`에 `restore_target_`을 건드리는 줄이 없어야 합니다.
3. `restore_target_ = nullptr;`이 복귀 성공 갈래 안에, 그리고 안쪽 `if`의 **바깥**에 정확히 하나 있어야 합니다.
4. `ShowDesktop`의 덮어쓰기 방지 조건이 그대로여야 합니다.
5. 나머지는 사용자 확인으로 넘기십시오. 판정 근거는 다음 하나입니다.
   - 최소화하고 **Ctrl에서 손을 뗀 뒤** 다시 Ctrl과 코너로 복귀했을 때, `restore hwnd`가 처음에 쓰던 창과 같다.

이 환경에서는 마우스와 키보드 입력을 합성할 수 없습니다. 사용자 화면에 입력을 밀어 넣으려고 하지 마십시오.

**빌드하려고 실행 중인 bamti를 종료했다면, 끝난 뒤 반드시 다시 띄워 놓으십시오.**

레지스트리에 쓰는 확인 절차는 넣지 마십시오.
