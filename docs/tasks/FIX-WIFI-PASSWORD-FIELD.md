# 수정 지시서: 비밀번호 입력란의 캐럿을 가운데 놓고 왼쪽에 라벨을 붙인다

> 작업 당시의 진단과 지시를 남긴 기록입니다. 현재 코드의 설명이 아닙니다.

`FIX-NETWORK-TOGGLE-CONNECT.md` 구현물을 사용자가 확인한 뒤 나온 요청 두 가지입니다.
건드리는 파일은 `src/wifi_password.cpp`이고, 라벨 폭을 재려면 `src/wifi_password.hpp`에 멤버가
하나 늘 수 있습니다.

**다른 것은 건드리지 마십시오.** 토글과 연결과 갈래 판정은 확인을 마쳤습니다.

---

## 1. 측정

사용자가 보낸 화면(`스크린샷 2026-09-05 111040.png`, 150% 배율)에서 잰 값입니다.

| 항목 | 실측 px | DIP |
| --- | ---: | ---: |
| 입력란 바깥 상자 | x 29..448, y 374..421 | 폭 280, 높이 32 |
| 캐럿 | x 44, y 374..398 | 높이 16.7 |
| 캐럿 중심 | y 386.0 | |
| 상자 중심 | y 397.5 | |

**캐럿이 11.5픽셀(7.7 DIP) 위로 쏠려 있습니다.** 캐럿의 위쪽 끝이 상자의 위쪽 경계와 정확히
같은 y(374)입니다. 즉 텍스트가 상자 맨 위에 붙어 그려지고 있습니다.

---

## 2. 캐럿을 세로 가운데로

### 2-1. 원인

단일 행 `EDIT`는 클라이언트 영역의 **위에서부터** 텍스트를 그립니다. 컨트롤 높이를 행 높이인
32 DIP로 잡아 두었기 때문에 글자와 캐럿이 위로 붙습니다.

**`EM_SETRECT`로 고치려 하지 마십시오.** 단일 행 편집 컨트롤은 이 메시지를 무시합니다.

### 2-2. 수정

`EDIT` 컨트롤 자체의 높이를 글자 한 줄 높이로 줄이고, 그 컨트롤을 행 안에서 세로 가운데에
놓으십시오. 행의 배경은 지금처럼 부모 창이 그립니다.

- 컨트롤 높이는 쓰고 있는 글꼴의 `TEXTMETRIC.tmHeight`에 위아래 여백 1 DIP씩을 더한 값으로
  잡으십시오. 숫자를 박지 말고 재서 쓰십시오. 배율이 바뀌면 글꼴 높이도 바뀝니다.
- 컨트롤의 `top`은 `행 중심 - 컨트롤 높이 / 2`입니다. 홀수 픽셀에서 반올림이 한쪽으로 몰리지
  않게 하십시오.
- `WM_CTLCOLOREDIT`에서 지금처럼 `bg_brush_`를 돌려주어 컨트롤과 행의 배경색을 같게 유지하십시오.
  높이를 줄이면 위아래가 부모 배경으로 드러나는데, 색이 같으면 이음매가 보이지 않습니다.
- 검증에서 캐럿 중심과 상자 중심의 차이가 1픽셀 이내여야 합니다.

---

## 3. 왼쪽에 라벨을 붙인다

지금은 입력란이 행 전체를 채우고 있어서, 처음 보는 사용자가 무엇을 넣는 칸인지 알 수 없습니다.

### 3-1. 문구

**`암호`입니다.** 다음 이유로 골랐습니다.

1. 이 패널의 다른 문구가 전부 한국어입니다. `알려진 네트워크`, `다른 네트워크`, `네트워크 설정…`
   사이에 영어 라벨 하나만 끼면 어긋납니다.
2. 맥 한국어판이 같은 자리에서 쓰는 말이 `암호`입니다. 이 패널은 맥 네트워크 메뉴를 재현합니다.
3. `비밀번호`보다 두 글자 짧아 입력란을 덜 잡아먹습니다.

영어로 바꾸라는 지시가 따로 오면 단수 `Password`를 쓰십시오. 값을 하나 받는 칸이므로 복수형은
틀립니다. 맥 영문판도 `Password:`입니다.

### 3-2. 자리

```
|← 14 →|암호|← 8 →|[            입력란            ]|← 14 →|
```

| 항목 | DIP |
| --- | ---: |
| 라벨 왼쪽 (콘텐츠 인셋) | 14 |
| 라벨과 입력란 사이 | 8 |
| 입력란 오른쪽 (콘텐츠 인셋) | 14 |

- 라벨 폭은 `GetTextExtentPoint32W`나 `DrawTextW`의 `DT_CALCRECT`로 재서 쓰십시오. 고정 폭을
  박으면 배율이나 글꼴이 바뀔 때 겹치거나 벌어집니다.
- 라벨은 행 안에서 세로 가운데 정렬입니다. 2-2절에서 가운데로 옮긴 캐럿과 글자의 기준선이 서로
  맞아야 합니다. 어긋나면 눈에 띕니다.
- 라벨 글자 크기는 목록 행의 SSID와 같은 **14 DIP**, 색은 흐린 색(`ScaleAlpha(fg, 0.55f)`에
  해당하는 값)입니다. SSID와 같은 진한 색으로 두면 라벨이 망 이름처럼 보입니다.
- 라벨은 부모 창이 직접 그리십시오. `STATIC` 컨트롤을 하나 더 만들면 배경색과 글꼴을 또 맞춰야
  합니다.

### 3-3. 입력란이 좁아지는 것

라벨이 들어가면 입력란이 대략 30 DIP 정도 좁아집니다. Wi-Fi 암호는 최대 63자라 다 보이지 않을 수
있는데, `EDIT`가 알아서 가로로 밀어 보여 주므로 그대로 두면 됩니다. 줄바꿈이나 폭 확장을 넣지
마십시오.

## 4. 검증

빌드는 Release 클린 빌드로 하고 경고가 없어야 합니다. **앱이 떠 있으면 링크가 막히므로
(`LNK1104`) 먼저 종료하십시오.**

1. **캐럿이 가운데인지.** 입력란을 띄우고 화면을 찍어, 캐럿의 중심과 상자의 중심을 픽셀로 재어
   차이가 1픽셀 이내인지 확인하고 **잰 값을 보고하십시오.** 눈으로만 보지 마십시오.
2. **글자를 넣었을 때도 가운데인지.** 점이 여러 개 찍힌 상태에서 다시 확인하십시오.
3. **라벨이 보이는지.** `암호`가 입력란 왼쪽에 있고, 라벨과 입력란이 겹치거나 벌어지지 않아야 합니다.
4. **배율 세 가지.** 100%, 150%, 200%에서 각각 확인하십시오. 라벨 폭을 재서 쓰지 않으면 여기서
   드러납니다.
5. **테마 두 가지.** 라이트와 다크에서 라벨이 읽히는지, 배경 이음매가 보이지 않는지 확인하십시오.
6. **긴 암호.** 40자 정도를 넣어 입력란이 가로로 밀리는지, 라벨을 침범하지 않는지 보십시오.
7. **기능이 그대로인지.** Enter로 연결이 시도되고 Esc로 입력란만 닫히는지 다시 확인하십시오.
   실제 연결까지 시도하면 세션이 끊길 수 있으니, **Wi-Fi를 끄거나 다른 망으로 갈아타지 마십시오.**
   틀린 암호를 넣어 실패 경로만 확인하면 충분합니다.

---

## 5. 보고할 것

- 입력란을 찍은 화면. 빈 상태와 글자를 넣은 상태, 라이트와 다크 각각.
- 1번과 2번에서 잰 캐럿 중심과 상자 중심의 픽셀 값.
- 컨트롤 높이를 무엇으로 계산했는지와 그 값이 150%에서 몇 픽셀이 됐는지.
- 라벨 폭을 잰 방법과 세 배율에서의 값.
