## 1. 서브메뉴가 6 DIP 아래로 내려가 있다

화면에서 `트레이 아이콘` 글자보다 서브메뉴 첫 항목인 `오피스키퍼` 글자가 조금 아래에 있습니다. 두 행의 세로 중심이 어긋납니다.

원인은 **서브메뉴를 여는 좌표가 자기 안쪽 여백을 셈하지 않은 것**입니다.

`PopupSurface::Place`의 `Anchor::RightOf` 갈래는 창의 위쪽 모서리를 넘겨받은 좌표에 그대로 둡니다.

```cpp
  if (mode == Anchor::RightOf) {
    x = anchor_screen.x;
    y = anchor_screen.y;
```

그런데 메뉴 안에서 첫 행은 창 위쪽 모서리가 아니라 `kMenuPadDip`(6 DIP)만큼 내려온 자리에서 시작합니다. `MenuRowRectOf`가 `int y = m.pad;`로 시작하기 때문입니다. 그래서 부모 행의 위쪽 모서리를 그대로 넘기면 첫 행이 정확히 6 DIP 아래에 놓입니다.

**독은 이미 옳게 하고 있습니다.** `src/dock.cpp`의 서브메뉴 열기를 보십시오.

```cpp
  const POINT anchor{row.right, row.top - Dip(kMenuPadDip)};
```

상단바만 빠져 있습니다. `src/menu_bar.cpp`의 `MenuBar::OpenBarSubmenu`에서

```cpp
  const POINT anchor{row.right, row.top};
```

를 다음으로 바꾸십시오.

```cpp
  const POINT anchor{row.right, row.top - DipToPx(kMenuPadDip, Dpi())};
```

`kMenuPadDip`은 `menu_style.hpp`가 이미 내보내고 있습니다. **이 한 줄이 전부입니다.** `PopupSurface::Place`는 건드리지 마십시오. 독이 그 함수를 같은 규약으로 쓰고 있으므로 그쪽을 고치면 독이 6 DIP 위로 올라갑니다.

## 2. 이름을 알 수 없는 `(숨김)` 항목이 다섯 개 남아 있다

`트레이 아이콘` 서브메뉴 아래쪽에 이런 행이 있습니다.

```
(숨김) 87b2b9
배터리
(숨김) 26d4ee
(숨김) 3539e4
(숨김) 5f9cef
(숨김) f584d0
```

### 2-1. 정체는 확인했다

사용자가 예전에 `이 아이콘 숨기기`로 숨겨 둔 트레이 아이콘들입니다. 설정 파일의 `tray_hidden_keys`에 키 여섯 개가 그대로 들어 있고, 화면의 여섯 행과 하나씩 대응합니다.

```json
"tray_hidden_keys": ["0x87b2b91452698293", "0xa5835428ce458fa8", "0x26d4ee49621ee1ba",
                     "0x3539e4318d4a9ab2", "0x5f9cef2252b04e8a", "0xf584d08a782d4029"]
```

`TrayMirror::MenuItems`의 두 번째 반복문이 이 키들을 훑으면서 `MenuLabel(tip, guid, true, key)`로 이름을 정하는데, `tip`도 비어 있고 `guid`도 비어 있으면 `HiddenKeyLabel`이 `(숨김) ` 뒤에 키 앞 여섯 자리를 붙입니다.

이름을 어디에서 얻는지가 핵심입니다. `last_tips_`라는 **프로세스 메모리 안의 표**입니다. 설정 파일에 저장되지 않으므로 bamti를 다시 띄우면 비어 있습니다.

여섯 개 중 `배터리` 하나만 이름이 나오는 것이 근거입니다. 배터리는 explorer가 항상 띄워 두는 시스템 아이콘이라 이번 실행에서도 훑혔고, 나머지 다섯은 그 앱이 지금 실행 중이 아니라 훑히지 않았습니다.

### 2-2. 무엇을 먼저 측정할 것인가

**위 설명은 가장 그럴듯한 가설이지 확정이 아닙니다.** 고치기 전에 다음을 로그로 확인하십시오.

`TrayMirror::MenuItems`에서 숨김 키마다 한 줄씩 남기십시오.

```cpp
Log(L"tray", L"hidden key=%s live=%d remembered=%d label=%s", ...);
```

- `live`: 지금 훑히는 아이콘 중에 같은 키가 있는가
- `remembered`: `last_tips_`에 그 키가 있는가

두 갈래로 결과가 갈립니다.

1. **`live=1`인데 `remembered=0`인 키가 있으면**, 실행 중인 앱인데도 이름을 기억하지 못하는 것입니다. 이때는 **`last_tips_`에 기록하는 자리가 숨김 걸러내기보다 뒤에 있어서** 숨긴 아이콘의 이름을 영영 못 배우는 것이 진짜 원인입니다. 기록을 걸러내기보다 앞으로 옮기십시오. 그러면 이름이 제대로 나오고 이 절의 나머지는 필요 없습니다.
2. **다섯 개가 모두 `live=0`이면** 가설대로입니다. 2-3절로 가십시오.

### 2-3. 이름을 모르는 항목은 메뉴에 넣지 않는다

`(숨김) 87b2b9`라는 행은 사용자에게 아무 정보도 주지 못합니다. 체크를 켜도 그 앱이 실행 중이 아니면 화면에 아무 변화가 없습니다. 목록만 어지럽힙니다.

`TrayMirror::MenuItems`의 두 번째 반복문에서, **이름을 정하지 못한 숨김 키는 `out`에 넣지 말고 건너뛰십시오.** 판단 기준은 `MenuLabel`이 `HiddenKeyLabel`로 떨어지는 경우, 곧 `LabelForGuid`도 실패하고 `tip`도 비어 있는 경우입니다.

`HiddenKeyLabel` 함수와 그 호출 경로를 지우지는 마십시오. 2-2절의 1번 갈래로 밝혀질 경우를 대비한 마지막 안전망으로 남겨 두고, 대신 그 자리에서 행을 만들지 않게만 하십시오.

### 2-4. 설정에서는 지우지 않는다

`settings.json`의 `tray_hidden_keys`에서 이 키들을 **지우지 마십시오.** 그 앱이 다시 실행되면 여전히 숨겨진 채로 있어야 합니다. 메뉴에 안 보이게 하는 것과 설정에서 없애는 것은 다른 일입니다.

사용자 설정 파일을 검증 과정에서 고쳐 쓰지 마십시오.

## 3. 검증

1. Release 클린 빌드가 경고 없이 통과해야 합니다.
2. **정렬.** 상단바를 우클릭해 `트레이 아이콘`에 마우스를 올리고, 부모 행의 글자와 서브메뉴 첫 행의 글자가 같은 높이에 오는지 화면으로 확인하십시오. `표시 항목`에서도 같은지 보십시오.
3. **독 회귀.** 독 아이콘 우클릭 메뉴의 `옵션` 서브메뉴 위치가 이 작업 전과 같아야 합니다.
4. **측정 로그.** 2-2절의 여섯 줄을 그대로 보고에 붙이십시오. 어느 갈래로 판정했는지 밝히십시오.
5. **숨김 항목.** 서브메뉴에서 `(숨김)`으로 시작하는 행이 사라져야 합니다. `배터리`처럼 이름이 있는 숨김 항목은 그대로 남아야 하고, 체크를 켜면 상단바에 다시 나타나야 합니다.
6. **설정 보존.** 작업 뒤 `settings.json`의 `tray_hidden_keys`에 키 여섯 개가 그대로 있어야 합니다.

레지스트리에 쓰는 확인 절차는 넣지 마십시오.
