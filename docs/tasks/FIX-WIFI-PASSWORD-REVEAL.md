# 수정 지시서: 암호 입력란에 보이기와 가리기를 바꾸는 눈 단추를 넣는다

> 작업 당시의 진단과 지시를 남긴 기록입니다. 현재 코드의 설명이 아닙니다.

`FIX-WIFI-PASSWORD-FIELD.md` 다음에 하십시오. 같은 행의 자리를 나눠 쓰므로 라벨과 캐럿 작업이
끝난 뒤에 얹어야 합니다.

건드리는 파일은 `src/wifi_password.cpp`와 `src/wifi_password.hpp`입니다.

---

## 1. 무엇을 만드는가

지금은 입력한 글자가 무조건 가려집니다. 오타를 확인할 방법이 없습니다.
**입력란 안쪽 오른쪽 끝에 눈 모양 단추를 넣고, 누를 때마다 가리기와 보이기를 바꾸십시오.**

```
|← 14 →|암호|← 8 →|[ ●●●●●●●●              (눈) ]|← 14 →|
                                          ↑ 입력란 안쪽
```

---

## 2. 아이콘

`C:\Windows\Fonts\SegoeIcons.ttf`를 실제로 렌더링해서 고른 값입니다. 추측이 아닙니다.

| 코드포인트 | 모양 | 언제 그리는가 |
| --- | --- | --- |
| `U+E890` | 뜬 눈 | **가려져 있을 때.** 누르면 보이게 된다는 뜻입니다. |
| `U+ED1A` | 사선이 그어진 눈 | **보이고 있을 때.** 누르면 다시 가려진다는 뜻입니다. |

- 지금 상태가 아니라 **누르면 일어날 일**을 그립니다. 널리 쓰이는 관행이고 이쪽이 직관적입니다.
- `U+E7B3`도 같은 눈 모양이지만 `U+E890`과 사실상 같은 글리프입니다. 짝이 되는 `U+ED1A`와
  이름이 맞는 `U+E890`을 쓰십시오.
- **두 글리프의 크기가 다릅니다.** 같은 크기로 그렸을 때 눈만 있는 `E890`은 세로로 40/80을,
  사선이 있는 `ED1A`는 64/80을 차지합니다. 사선이 대각선으로 뻗기 때문입니다. 눈 자체의 크기는
  같으므로 폰트 크기는 같게 두고, **상자를 넉넉히 잡아 사선의 양 끝이 잘리지 않게 하십시오.**
  단추를 눌렀을 때 아이콘이 커졌다 작아졌다 하는 것처럼 보이면 상자가 좁은 것입니다.
- Segoe Fluent Icons가 없는 환경을 위해 물러설 글자를 정해 두십시오. 이 저장소는 이미
  `DrawFluentOrFallback`에서 같은 방식을 씁니다.

## 3. 자리와 크기

| 항목 | DIP |
| --- | ---: |
| 단추 상자 | 24 × 24 |
| 아이콘 크기 | 16 |
| 단추 오른쪽 → 입력란 안쪽 오른쪽 | 4 |
| 단추 왼쪽 → 글자 영역 오른쪽 | 4 |

- 단추는 입력란 사각형 **안쪽**입니다. 사각형 밖으로 나가지 않게 하십시오.
- 세로는 입력란 안에서 가운데 정렬입니다.
- **글자가 단추 밑으로 흘러 들어가지 않게 하십시오.** `EM_SETMARGINS`에 `EC_RIGHTMARGIN`을 주어
  오른쪽 여백을 `단추 폭 + 8`만큼 잡습니다. 이것을 빼먹으면 긴 암호를 넣었을 때 글자가 눈 아래로
  들어가 겹칩니다.

```cpp
SendMessageW(edit_, EM_SETMARGINS, EC_RIGHTMARGIN, MAKELPARAM(0, right_px));
```

- 마우스를 올리면 단추 자리에 원형 강조를 깔아 누를 수 있음을 보이십시오. 색은 행의 호버와 같은
  계열로 맞추고, 원의 지름은 단추 상자와 같습니다.

## 4. 동작

### 4-1. 가리기와 보이기를 바꾼다

**`ES_PASSWORD` 스타일을 켰다 껐다 하지 마십시오.** 창 스타일을 바꾸면 컨트롤을 다시 만들어야
하는 경우가 있습니다. `EM_SETPASSWORDCHAR`를 쓰십시오.

```cpp
// 보이기
SendMessageW(edit_, EM_SETPASSWORDCHAR, 0, 0);
// 가리기 (원래 문자로 되돌린다)
SendMessageW(edit_, EM_SETPASSWORDCHAR, mask_char_, 0);
```

- `mask_char_`는 창을 만든 직후에 `EM_GETPASSWORDCHAR`로 한 번 읽어 저장해 두십시오.
  `L'*'`이나 `L'●'`을 직접 박지 마십시오. 시스템과 테마에 따라 다릅니다.
- **바꾼 뒤에 `InvalidateRect(edit_, nullptr, TRUE)`를 부르십시오.** 이걸 빼면 이미 그려진 글자가
  그대로 남아 눌러도 안 바뀌는 것처럼 보입니다.
- 캐럿 위치와 선택 범위가 흐트러지지 않는지 확인하십시오. 흐트러지면
  `EM_GETSEL`로 저장하고 `EM_SETSEL`로 되돌리십시오.

### 4-2. 포커스를 빼앗지 않는다

단추를 `BUTTON` 컨트롤로 만들지 말고 **부모 창이 직접 그리고 직접 히트 테스트하십시오.**
자식 컨트롤을 만들면 클릭할 때 포커스가 그쪽으로 넘어가 캐럿이 사라집니다.

- `WM_LBUTTONDOWN`에서 단추 영역이면 상태를 바꾸고, 처리 끝에 `SetFocus(edit_)`로 포커스를
  입력란에 되돌리십시오.
- 단추를 눌러도 입력을 이어서 할 수 있어야 합니다. 누른 뒤 바로 타자를 쳐서 확인하십시오.

### 4-3. 열 때는 항상 가려진 상태로

창을 닫거나 다시 열 때 **반드시 가리기 상태로 되돌리십시오.** 앞서 보이기로 두었다고 해서 다음
망의 암호까지 그대로 드러나면 안 됩니다. `Show`에서 초기화하는 것이 가장 확실합니다.

### 4-4. 로그

**보이기 상태로 바꿨다는 사실조차 값과 함께 남기지 마십시오.** 지금까지 지킨 대로 암호는 어떤
형태로도 로그에 남기지 않습니다. 단추를 눌렀다는 기록 자체가 필요하지 않습니다.

## 5. 검증

빌드는 Release 클린 빌드로 하고 경고가 없어야 합니다. **앱이 떠 있으면 링크가 막히므로
(`LNK1104`) 먼저 종료하십시오.**

1. **바뀌는지.** 글자를 몇 자 넣고 단추를 눌러 가려진 글자가 그대로 보이는지, 다시 눌러 가려지는지
   확인하십시오.
2. **아이콘이 바뀌는지.** 가려졌을 때 뜬 눈, 보일 때 사선 눈인지 보십시오. 반대로 되어 있으면
   2절의 표를 다시 읽으십시오.
3. **사선이 잘리지 않는지.** 사선 눈의 양 끝이 상자 밖으로 잘려 나가지 않아야 합니다.
4. **포커스가 남는지.** 단추를 누른 직후에 바로 타자를 쳐서 글자가 입력란에 들어가는지 보십시오.
5. **긴 암호.** 40자 정도를 넣어 글자가 눈 아래로 들어가 겹치지 않는지 보십시오.
   겹치면 `EM_SETMARGINS`가 빠진 것입니다.
6. **다시 열면 가려지는지.** 보이기로 둔 채 Esc로 닫고 다른 망을 눌러 다시 열었을 때, 가려진
   상태로 시작하는지 확인하십시오.
7. **캐럿이 그대로인지.** 글자 중간에 캐럿을 두고 단추를 눌렀을 때 캐럿이 끝으로 튀지 않는지
   보십시오.
8. **배율 세 가지와 테마 두 가지.** 100%, 150%, 200%에서, 라이트와 다크에서 각각 확인하십시오.
9. **앞의 작업이 그대로인지.** 캐럿이 여전히 세로 가운데인지, `암호` 라벨이 제자리인지 다시
   확인하십시오.

**Wi-Fi를 끄거나 다른 망으로 갈아타지 마십시오.** 세션이 끊깁니다. 틀린 암호로 실패 경로만
확인하면 충분합니다.

## 6. 보고할 것

- 가려진 상태와 보이는 상태를 각각 찍은 화면. 라이트와 다크 각각.
- 5번에서 쓴 오른쪽 여백 값과 그것을 어떻게 계산했는지.
- 물러설 글자로 무엇을 골랐는지.
- 7번에서 캐럿 위치를 되돌리는 처리가 필요했는지.
