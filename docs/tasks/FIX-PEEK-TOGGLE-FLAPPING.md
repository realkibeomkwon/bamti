# 작업 지시서: 코너를 스칠 때마다 전환되는 것을 멈춘다

> 작업 당시의 진단과 지시를 남긴 기록입니다. 현재 코드의 설명이 아닙니다.

`PROBE-CTRL-DRAG-CONTINUOUS.md`(커밋 `f93d820`)의 후속입니다. 건드리는 파일은 `src/menu_bar.cpp`와 `src/menu_bar.hpp`입니다.

## 1. 지난 탐침으로 닫힌 갈래

**드래그 도중에도 Ctrl은 완전하게 보입니다. 이 방향은 더 파지 마십시오.**

```
13:42:33.866 probe hook=701 lastvk=162 lastmsg=0x00000100 async_c=1 keystate_c=1 lbtn=1
13:42:34.078 probe hook=707 lastvk=162 lastmsg=0x00000100 async_c=1 keystate_c=1 lbtn=1
```

훅 계수기가 매 틱 오르고, 훅이 마지막으로 본 키가 왼쪽 Ctrl(162)이며, `GetAsyncKeyState`와 `GetKeyState`도 모두 눌림을 봅니다. 같은 드래그 구간에서 최소화까지 실제로 성공했습니다.

```
13:42:33.844 [peek] dwell fire
13:42:34.046 [peek] MinimizeAll hr=0x00000000 iconic_before=0 iconic_after=1 cls=Zed::Window
```

커밋 `349aa48`의 수정은 의도대로 작동하고 있습니다.

## 2. 측정: 한 번 누르는 동안 전환이 네 번 일어난다

사용자가 "될 때도 있고 안 될 때도 있다"고 보고했습니다. 원인은 **한 번의 Ctrl 유지 안에서 전환이 여러 번 일어나는 것**입니다.

```
13:49:35.490 [peek] watch on=1
13:49:36.373 [peek] dwell fire
13:49:36.568 [peek] UndoMinimizeALL iconic_before=1 iconic_after=0
13:49:36.935 [peek] dwell fire
13:49:37.129 [peek] MinimizeAll     iconic_before=0 iconic_after=1
13:49:37.932 [peek] dwell fire
13:49:38.128 [peek] UndoMinimizeALL iconic_before=1 iconic_after=0
13:49:38.868 [peek] dwell fire
13:49:39.072 [peek] MinimizeAll     iconic_before=0 iconic_after=1
13:49:40.151 [peek] watch on=0
```

Ctrl을 5초 남짓 누르고 있는 동안 전환이 네 번 일어났습니다. 최소화와 복귀가 짝을 이루어 상쇄되므로, **사용자 눈에는 아무 일도 일어나지 않은 것처럼 보입니다.** 홀수 번으로 끝나면 되는 것처럼 보이고 짝수 번으로 끝나면 안 되는 것처럼 보이므로, "될 때가 있고 안 될 때가 있다"는 보고와 정확히 맞습니다.

원인은 걸쇠를 푸는 조건입니다. 30밀리초 감시 타이머는 커서가 코너 구역을 벗어나는 즉시 `unlatch reason=corner-left`를 남기고 걸쇠를 풉니다. 그런데 코너 구역은 우측 끝에서 `kPeekZoneDip`(14 DIP)뿐입니다. 실제로 벗어난 지점을 보십시오.

```
13:49:37.144 [peek] corner in=0 x=5096 y=20 right=5120
```

우측 끝에서 겨우 24픽셀 떨어진 자리입니다. 손이 이만큼만 흔들려도 걸쇠가 풀리고, 다시 들어오면 120밀리초 뒤에 또 전환됩니다.

## 3. 측정: 되살릴 창이 오염된다

사용자가 "복귀했더니 원래 창이 아니라 Chrome이 맨 앞이었다"고 보고했습니다.

되살릴 창은 `ShowDesktop`에서 그 순간의 전경 창으로 잡습니다. 2절의 반복 전환 때문에, **복귀 직후 셸이 앞에 올려놓은 임의의 창이 곧바로 다음 최소화에서 되살릴 창으로 기록됩니다.** 사용자가 원래 쓰던 창은 그 시점에 이미 잊힙니다.

더 분명한 기록도 있습니다. 바탕 화면 자체를 되살릴 창으로 올린 경우입니다.

```
13:42:38.854 [peek] MinimizeAll     fg_before=0000000000010104 cls=Progman
13:42:39.942 [peek] UndoMinimizeALL fg_before=0000000000010104 cls=Progman
13:42:39.944 [peek] restore hwnd=0000000000010104 zorder=1 fg=1
```

`0x10104`는 `Progman`, 곧 바탕 화면입니다. 사용자가 바탕 화면 위에서 드래그하는 동안 전환이 일어나면 바탕 화면을 되살릴 창으로 기억하고, 복귀할 때 그것을 맨 앞으로 올립니다.

---

## 4. 고칠 것

### 4-1. 걸쇠에 재무장 구역을 둔다

**이것이 이 지시서의 핵심입니다.**

지금은 코너 구역을 벗어나는 것만으로 걸쇠가 풀립니다. 앞으로는 **재무장 구역 밖으로 나가야** 풀리게 하십시오.

상수를 하나 더합니다. 값은 96 DIP으로 시작하십시오.

```cpp
constexpr int kPeekRearmZoneDip = 96;  // 걸쇠를 다시 걸 수 있게 되는 거리.
```

30밀리초 감시 타이머(`kCornerWatchTimerId`) 안에서 판정을 둘로 나눕니다.

```
발동 판정 (지금 그대로): 상단바 안이면서 우측 끝에서 kPeekZoneDip 안
해제 판정 (새로 만듦):   우측 끝에서 kPeekRearmZoneDip보다 멀다
```

`hit`이 거짓이 되었을 때 무조건 `StopDesktopPeek`을 부르지 말고, **해제 판정을 통과했을 때만** 부르십시오. 뜸 타이머를 죽이는 것은 지금처럼 `hit`이 거짓이 되면 바로 하십시오. 뜸이 아직 안 터졌으면 코너를 벗어난 순간 취소되는 것이 맞습니다.

해제 판정에서는 **세로 위치를 따지지 마십시오.** 커서가 상단바 아래로 조금 내려간 것만으로 걸쇠가 풀리면 지금 증상이 그대로 남습니다. 가로 거리 하나만 봅니다.

`unlatch reason=corner-left`는 그대로 두십시오. 해제 판정이 바뀌었으므로 이 줄이 훨씬 드물게 남아야 하고, 그것이 곧 이번 수정의 검증 근거입니다.

### 4-2. 되살릴 창을 한 번만 잡는다

`ShowDesktop`에서 `restore_target_`을 잡는 자리를 두 가지로 고치십시오.

**첫째, 바탕 화면과 우리 창은 대상에서 뺍니다.** 전경 창의 클래스 이름이 `Progman` 또는 `WorkerW`이거나, 그 창이 우리 상단바(`hwnd_`)이면 `restore_target_`을 `nullptr`로 두십시오. 되살릴 창이 없는 것이 엉뚱한 창을 올리는 것보다 낫습니다.

**둘째, 이미 유효한 대상이 있으면 덮어쓰지 마십시오.**

```
restore_target_이 nullptr이 아니고 IsWindow도 참이면 → 그대로 둔다
그렇지 않으면 → 위의 첫째 규칙에 따라 새로 잡는다
```

그리고 복귀에 성공한 뒤 `restore_target_`을 비우는 지금 코드(`restore_target_ = nullptr;`)를 **지우십시오.** 대신 `StopCornerWatch`에서 비우십시오. 곧 되살릴 창의 수명은 "Ctrl을 누르고 있는 한 번의 구간"입니다. 이렇게 하면 한 번 누르는 동안 여러 번 전환되더라도 항상 처음에 쓰던 창으로 돌아옵니다.

### 4-3. 어느 갈래로 갔는지 한 줄 남긴다

`StartDesktopPeek`에서 전환하기 직전에 한 줄 남기십시오. 전환이 실제로 일어날 때만 남으므로 로그가 자라지 않습니다.

```
[peek] toggle shown=%d target=%p cls=%s
```

`shown`은 `desktop_shown_`의 값이고, `target`과 `cls`는 그 시점 `restore_target_`과 그 창의 클래스 이름입니다.

**이 줄이 필요한 이유는 아직 확인하지 못한 가설이 하나 남아 있기 때문입니다.** 사용자가 Win+D나 작업 표시줄로 창을 직접 되살리면 `desktop_shown_`이 실제 상태와 어긋나고, 그 뒤로는 반대 방향으로 호출되어 화면이 움직이지 않습니다. 이번에는 고치지 말고 기록만 남기십시오. 다음 관측에서 `shown` 값과 실제 화면이 어긋나는 순간이 잡히면 그때 고칩니다.

## 5. 하지 말 것

- **뜸(`kDesktopPeekDwellMs`, 120밀리초), 감시 주기(`kCornerWatchMs`, 30밀리초), 코너 폭(`kPeekZoneDip`, 14 DIP)을 건드리지 마십시오.** 발동 조건은 그대로입니다. 이번에 바꾸는 것은 해제 조건뿐입니다.
- **Ctrl을 뗄 때 자동으로 복귀시키지 마십시오.** 지금 동작은 토글이고, 그 설계를 바꾸는 것은 이번 범위가 아닙니다.
- `desktop_shown_`을 실제 상태로 다시 맞추는 코드를 넣지 마십시오. 4-3절의 기록만 남깁니다.
- Win+D를 흉내 내지 마십시오. `FIX-RESTORE-ACTIVE-WINDOW.md` 2절에서 이미 배제한 방법입니다.
- 훅 안에서 로그를 부르지 마십시오.
- 지난 탐침(`LogCtrlProbeIfChanged`)은 그대로 두십시오. 이번 수정을 확인한 뒤에 별도 지시서로 걷어냅니다.

## 6. 검증

1. Release 클린 빌드가 경고 없이 통과해야 합니다.
2. 해제 판정이 가로 거리 하나만 보는지 코드로 확인하십시오. 세로 위치나 `PtInRect`가 해제 판정에 들어가면 안 됩니다.
3. 복귀에 성공한 뒤 `restore_target_`을 비우는 코드가 없어야 하고, `StopCornerWatch`에는 있어야 합니다.
4. `StartDesktopPeek`의 새 로그가 전환할 때만 남는지 확인하십시오. 감시 타이머나 뜸 타이머 자리에 로그를 넣으면 안 됩니다.
5. 나머지는 사용자 확인으로 넘기십시오. 판정 근거는 다음 둘입니다.
   - Ctrl을 누른 채 코너에 한 번 다녀오면 `dwell fire`가 **한 번만** 남는다.
   - 복귀했을 때 `restore hwnd`가 처음에 쓰던 창과 같다.

이 환경에서는 마우스와 키보드 입력을 합성할 수 없습니다. 사용자 화면에 입력을 밀어 넣으려고 하지 마십시오.

**빌드하려고 실행 중인 bamti를 종료했다면, 끝난 뒤 반드시 다시 띄워 놓으십시오.**

레지스트리에 쓰는 확인 절차는 넣지 마십시오.
