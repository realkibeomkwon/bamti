# 작업 지시서: 바탕 화면 보기를 임시 미리 보기에서 토글로 바꾼다

> 작업 당시의 진단과 지시를 남긴 기록입니다. 현재 코드의 설명이 아닙니다.

`TASK-BAR-SHOW-DESKTOP.md`와 `FIX-PEEK-CTRL-STALE.md`(커밋 `e439519`, `9bb5f31`)를 대체합니다. `FIX-BAR-MENU-POLISH.md` 다음에 하십시오. 둘 다 `src/menu_bar.cpp`를 건드립니다.

건드리는 파일은 `src/menu_bar.cpp`, `src/menu_bar.hpp`, `src/live_preview.cpp`, `src/live_preview.hpp`, `CMakeLists.txt`, `bamti.vcxproj`입니다.

---

## 1. 무엇을 바꾸는가

지금은 Ctrl을 누른 채 상단바 오른쪽 끝에 올리면 **머무는 동안만** 창들이 투명해지고, 마우스를 옮기면 원래 화면으로 돌아옵니다. 미리 보기입니다.

**이것을 토글로 바꿉니다.**

1. Ctrl을 누른 채 오른쪽 끝에 300밀리초 머문다 → 모든 창이 실제로 최소화되어 바탕 화면이 드러난다. **마우스를 옮겨도 그대로 있다.**
2. 다시 Ctrl을 누른 채 오른쪽 끝에 머문다 → 창들이 원래대로 돌아온다.

Windows 작업 표시줄 맨 오른쪽 끝을 누르는 것과 같은 동작입니다.

---

## 2. 가능하다 (측정 확인)

문서화된 `IShellDispatch4::ToggleDesktop`을 씁니다. `Shell.Application`(`CLSID_Shell`)에서 얻습니다. 이 컴퓨터에서 해당 개체에 다음 세 메서드가 모두 있는 것을 확인했습니다.

```
ToggleDesktop       Method
MinimizeAll         Method
UndoMinimizeALL     Method
```

**`ToggleDesktop`만 쓰십시오.** 지금 상태가 어느 쪽인지 우리가 기억할 필요가 없습니다. 바탕 화면이 드러나 있는지 아닌지는 셸이 들고 있고, 부를 때마다 반대로 뒤집어 줍니다. **우리 쪽에 상태 변수를 두지 마십시오.** 사용자가 그 사이에 창을 직접 복원해도 셸의 판단을 따라가는 편이 옳습니다.

`Shell.Application`은 COM이 필요합니다. `src/winx_menu.cpp`의 `ComScope`와 같은 방식으로 초기화 상태를 확인하고, `IDispatch`를 `IShellDispatch4`로 질의하십시오. 실패한 단계를 로그로 남기십시오.

한 가지 확인할 것이 있습니다. **bamti는 Windows 작업 표시줄을 감춥니다.** 이 상태에서도 `ToggleDesktop`이 동작하는지 실제로 눌러서 확인하고 결과를 보고하십시오. 셸 서비스가 하는 일이라 작업 표시줄 창과 무관할 것으로 보지만, 확인되지 않은 추측입니다.

---

## 3. 한 번만 발동해야 한다

토글이므로 **머무는 동안 계속 부르면 창이 깜빡이며 오르내립니다.** 진입할 때 딱 한 번만 발동해야 합니다.

`bool peek_latched_ = false;` 하나를 둡니다.

- 조건(Ctrl이 눌렸고 오른쪽 끝 영역 안이다)이 만족되어 300밀리초 뜸이 지나면, `peek_latched_`가 거짓일 때만 `ToggleDesktop`을 부르고 참으로 바꿉니다.
- **조건이 깨지면 `peek_latched_`를 거짓으로 되돌립니다.** 마우스가 영역을 벗어났거나, 상단바 밖으로 나갔거나(`WM_MOUSELEAVE`), Ctrl에서 손을 뗐을 때입니다.

즉 다시 발동하려면 **영역을 벗어났다가 돌아오거나 Ctrl을 놓았다 다시 눌러야** 합니다. 이것이 이 절의 요점입니다.

Ctrl 해제는 지금처럼 100밀리초 폴링으로 봅니다. 상단바는 `WS_EX_NOACTIVATE`라 키보드 메시지를 받지 못하기 때문입니다. 다만 **이제 폴링이 하는 일은 걸쇠를 푸는 것뿐입니다.** 화면을 되돌리면 안 됩니다.

폴링 타이머는 걸쇠가 걸려 있는 동안에만 돌리고, 걸쇠가 풀리면 죽이십시오.

`DesktopPeekWanted`의 판정 조건(전체 화면, 재정렬 중, 팝업 열림, Ctrl 눌림, 영역 안)은 지금 것을 그대로 씁니다. `GetAsyncKeyState`만 보는 것도 그대로 둡니다.

## 4. 미리 보기 코드를 걷어낸다

`SetLivePreview`를 부르는 곳이 없어집니다.

- `src/live_preview.cpp`와 `src/live_preview.hpp`를 지우고 `CMakeLists.txt`와 `bamti.vcxproj`에서도 빼십시오.
- `src/menu_bar.cpp`의 `#include "live_preview.hpp"`와 `LivePreviewAvailable()` 호출을 지웁니다.
- `WM_DESTROY`와 `SetFullscreenOccluded`에서 미리 보기를 해제하던 자리는 **더 이상 필요 없습니다.** 창이 실제로 최소화된 것이므로 bamti가 종료해도 되돌릴 것이 없습니다. 걸쇠만 풀고 타이머만 죽이십시오.

서수 113으로 알아낸 사실은 `TASK-BAR-SHOW-DESKTOP.md`에 남아 있으므로 코드에서 지워도 기록은 사라지지 않습니다.

## 5. 검증

1. Release 클린 빌드가 경고 없이 통과해야 합니다.
2. **토글 동작.** 창을 몇 개 띄우고 Ctrl을 누른 채 상단바 오른쪽 끝에 300밀리초 머무르십시오. 창이 전부 최소화되어야 합니다. **마우스를 다른 곳으로 옮겨도 바탕 화면이 그대로여야 합니다.**
3. **되돌리기.** 다시 Ctrl을 누른 채 같은 자리에 머무르면 창이 원래대로 돌아와야 합니다.
4. **한 번만 발동.** 2번 상태에서 마우스를 영역 안에 둔 채 Ctrl을 계속 누르고 있으십시오. **창이 오르내리며 깜빡이면 안 됩니다.** 걸쇠가 제대로 걸린 것입니다.
5. **걸쇠 풀림.** 영역을 벗어났다가 다시 들어오면 발동해야 합니다. Ctrl을 놓았다 다시 눌러도 발동해야 합니다.
6. **작업 표시줄이 숨겨진 상태에서의 동작.** 2절의 확인 결과를 보고에 적으십시오.
7. **회귀.** Ctrl을 누른 채 위젯을 끌어 순서를 바꾸는 기능이 그대로 동작해야 하고, 오른쪽 끝까지 끌고 가도 바탕 화면 보기가 발동하면 안 됩니다.

이 환경에서는 마우스와 키보드 입력을 합성할 수 없습니다. **사용자 화면에 입력을 밀어 넣으려고 하지 마십시오.** 실제 키가 필요한 항목은 코드 경로를 설명하고 사용자 확인으로 넘기십시오.

**검증하겠다고 사용자의 창을 최소화한 채로 두지 마십시오.** 확인한 뒤에는 반드시 되돌려 놓으십시오.

레지스트리에 쓰는 확인 절차는 넣지 마십시오. 전원이나 세션에 손대는 확인 절차도 넣지 마십시오.
