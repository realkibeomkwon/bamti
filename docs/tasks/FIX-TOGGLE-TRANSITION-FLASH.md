# 작업 지시서: 전환 도중 중간 창이 드러나는 것을 없앤다

> 작업 당시의 진단과 지시를 남긴 기록입니다. 현재 코드의 설명이 아닙니다.

건드리는 파일은 `src/desktop_toggle.cpp`, `src/desktop_toggle.hpp`, `src/dwm.hpp`입니다. `src/task_list.cpp`의 `HideHwnds`와 `RestoreHwnds`는 독에서도 쓰므로 **건드리지 마십시오.**

바탕 화면 전환의 나머지는 모두 동작합니다. 처음 보고된 세 증상 중 **마지막 하나만** 남았습니다.

---

## 1. 남은 증상

전환이 끝나기 전에 중간에 있던 다른 창이 드러났다가 사라지는 것이 보입니다. 감추는 쪽과 되살리는 쪽 모두 해당합니다.

`TASK-DESKTOP-TOGGLE-REWRITE.md` 3절에서 **뒤에 있는 창부터 최소화하면 맨 앞 창이 마지막까지 화면을 덮으므로 중간이 드러나지 않는다**고 보았고, 그대로 구현되어 있습니다. **그 판단이 불완전했습니다.**

---

## 2. 순서만으로는 안 되는 이유 둘

### 2-1. 최소화 애니메이션이 창을 스스로 걷어냅니다

`ShowWindow(hwnd, SW_SHOWMINNOACTIVE)`는 창을 즉시 없애지 않고 **작업 표시줄 쪽으로 오므라드는 전환 효과**를 시작합니다. 그 효과가 도는 200밀리초 남짓 동안 창은 점점 작아지고, **덮고 있던 자리가 그만큼 드러납니다.**

곧 "맨 앞 창이 마지막까지 화면을 덮는다"는 전제가 성립하지 않습니다. 맨 앞 창은 자기 차례가 오기 전에 이미 오므라들고 있는 뒤쪽 창들을 가려 주지만, **자기가 오므라들 때 그 아래를 열어 보입니다.** 뒤쪽 창들이 아직 다 사라지지 않았다면 그것이 보입니다.

### 2-2. 다른 프로세스의 창에 건 `ShowWindow`는 비동기입니다

`HideHwnds`가 도는 순서는 **호출 순서일 뿐 완료 순서가 아닙니다.** 각 창은 저마다 다른 프로세스에 속하고, `ShowWindow`는 그 프로세스의 스레드에 요청을 넘기고 곧바로 돌아옵니다.

응답이 빠른 프로세스와 느린 프로세스가 섞여 있으면 **나중에 부른 맨 앞 창이 먼저 사라지는 일이 실제로 생깁니다.** 그러면 뒤쪽 창이 그대로 드러납니다.

**두 이유 모두 순서를 어떻게 바꿔도 없어지지 않습니다.** 전환 효과 자체를 끄는 것이 답입니다.

---

## 3. 고칠 것

### 3-1. 창마다 DWM 전환 효과를 끕니다

`DwmSetWindowAttribute`의 `DWMWA_TRANSITIONS_FORCEDISABLED`(값 3)를 씁니다. **창 하나에만 걸리는 속성이고 시스템 전역 설정이 아닙니다.**

`src/dwm.hpp`의 기존 상수 옆에 더하십시오.

```cpp
inline constexpr DWORD kTransitionsForceDisabled = 3;
```

이 저장소는 `DwmSetWindowAttribute`를 이미 여러 곳에서 쓰고 `dwmapi`도 링크되어 있으므로 빌드 설정은 바꿀 것이 없습니다.

### 3-2. 감출 때 끄고, 되살린 뒤에 되돌립니다

`DesktopToggle`에 도우미를 두십시오.

```cpp
// 창 하나의 DWM 전환 효과를 끄거나 되돌린다.
// 다른 프로세스의 창에도 걸린다. 실패는 무시한다. 효과가 남아 있어도
// 동작에는 지장이 없고, 창이 이미 사라진 뒤일 수 있다.
void SetTransitions(HWND hwnd, bool enabled);
```

`Conceal`은 **최소화하기 전에** 대상 창 전부의 효과를 끕니다.

```
1. 이번에 감출 창 전부에 SetTransitions(hwnd, false)
2. 지금처럼 뒤집은 사본을 HideHwnds 에 넘긴다      // 순서는 그대로 둔다
3. 지금처럼 목록을 합친다
```

**2번의 순서 뒤집기를 없애지 마십시오.** 2-2절의 비동기 문제는 효과를 꺼도 남습니다. 다만 효과가 없으면 창이 한 프레임에 사라지므로 어긋나는 폭이 훨씬 좁아지고, 순서까지 맞으면 눈에 띌 일이 없습니다. **두 대책을 함께 씁니다.**

`Reveal`은 **되살린 뒤에** 되돌립니다.

```
1. RestoreHwnds(concealed_)                        // 지금과 같다
2. concealed_ 의 살아 있는 창마다 SetTransitions(hwnd, true)
3. concealed_ 를 비운다
4. 로그: reveal n=<개수>                            // 지금과 같다
```

곧 **우리가 창을 맡고 있는 동안만 효과가 꺼져 있습니다.** 돌려줄 때 원래대로 되돌립니다.

### 3-3. 뒷정리를 반드시 넣으십시오

우리가 끈 것을 되돌리지 못한 채 끝나면 사용자의 창은 전환 효과가 꺼진 채로 남습니다. 눈에 잘 띄지 않는 데다 사용자가 원인을 짐작할 수 없으므로 **반드시 막아야 합니다.**

`DesktopToggle`의 소멸자에서 `concealed_`에 남아 있는 살아 있는 창의 효과를 되돌리십시오. `MenuBar`가 멤버로 들고 있으므로 앱이 정상 종료하면 함께 불립니다.

**되살리기 없이 감추기만 두 번 이어질 때도 새어 나가지 않는지 확인하십시오.** `Conceal`이 합친 목록을 들고 있고 `Reveal`이 그 전체를 되돌리므로 지금 설계로 새지 않아야 하지만, 코드로 그러한지 눈으로 짚어 보십시오.

---

## 4. 이것으로도 남으면

**효과를 껐는데도 중간 창이 보이면 더 손대지 말고 보고하십시오.** 그때는 원인이 2-2절의 비동기 쪽이고, 다음 후보는 창이 실제로 최소화되었는지 짧게 기다렸다가 다음 창으로 넘어가는 방식입니다. 그 방식은 UI 스레드를 붙잡을 위험이 있어서 별도로 판단해야 합니다. **이번 지시서에서 그것까지 하지 마십시오.**

---

## 5. 검증

### 5-1. 빌드

Release 빌드가 경고 없이 통과해야 합니다.

### 5-2. 로그

`conceal`과 `reveal` 줄의 모양은 바뀌지 않습니다. **전환 효과를 끄고 켠 것을 로그로 남기지 마십시오.** 창 개수만큼 줄이 쌓입니다.

### 5-3. 사용자 확인으로 넘길 것

**이 환경에서는 마우스와 키보드 입력을 합성할 수 없습니다. 사용자 화면에 입력을 밀어 넣으려고 하지 마십시오.**

| # | 확인 | 결과 |
| --- | --- | --- |
| 1 | 감출 때 중간 창이 드러나 보이지 않음 | |
| 2 | 되살릴 때 중간 창이 드러나 보이지 않음 | |
| 3 | 되살린 뒤 그 창들을 손으로 최소화하면 **평소의 오므라드는 효과가 돌아옴** | |
| 4 | 전환 열 번 왕복 뒤에도 창이 사라지거나 순서가 어긋나지 않음 | |

**3번을 빠뜨리지 마십시오.** 우리가 끈 효과를 제대로 되돌렸는지 보는 유일한 방법입니다. 효과가 돌아오지 않으면 3-2절의 되돌리기나 3-3절의 뒷정리가 동작하지 않는 것입니다.

## 6. 하지 말 것

- **`SystemParametersInfo`로 `SPI_SETANIMATION`이나 `SPI_SETCLIENTAREAANIMATION`을 건드리지 마십시오.** 시스템 전역 설정이라 다른 앱까지 바뀌고, 되돌리지 못하면 사용자 설정이 망가집니다. 반드시 창 단위 속성만 씁니다.
- 레지스트리에 쓰지 마십시오. 확인 절차에도 넣지 마십시오.
- `src/task_list.cpp`의 `HideHwnds`와 `RestoreHwnds`를 바꾸지 마십시오. 독의 창 조작이 같은 함수를 씁니다.
- `Conceal`의 순서 뒤집기를 없애지 마십시오. 2-2절 때문에 여전히 필요합니다.
- 감지부(훅, `CtrlHeld`, 예비 폴링, 감시 주기, 뜸, 걸쇠, 코너 폭)를 건드리지 마십시오.
- 창이 최소화되기를 기다리는 대기 반복문을 넣지 마십시오. 4절의 사정이 있습니다.
- `ShowWindow(SW_HIDE)`로 사용자 창을 감추지 마십시오.
- 이번 범위 밖의 파일을 정리하거나 이름을 바꾸지 마십시오.

**빌드하려고 실행 중인 bamti를 종료했다면, 끝난 뒤 반드시 다시 띄워 놓으십시오.**
