# 작업 지시서: 훅이 기억하는 Win 눌림 상태를 실제 키 상태로 검증한다

> 작업 당시의 진단과 지시를 남긴 기록입니다. 현재 코드의 설명이 아닙니다.

`FIX-HOOK-LOG-FLOOD.md`(커밋 `70e4f25`)의 후속입니다. 건드리는 파일은 `src/menu_bar.cpp`입니다.

---

## 1. 문제: 기억이 어긋나면 모든 키에 Win이 섞인다

`LowLevelKeyboardProc`에 이런 갈래가 있습니다.

```cpp
  } else if (g_win_held && down) {
    ...
    if (!g_win_combo) {
      g_win_combo = true;
      g_win_injected = true;
      InjectWinKey(g_win_vk, false);   // Win 누름을 시스템에 주입한다
    }
  }
```

Win 키를 누른 채 다른 키를 누르면, 삼켰던 Win 누름을 그때 주입해서 조합키를 살리는 구조입니다. 의도는 옳습니다.

**위험한 것은 `g_win_held`가 기억이라는 점입니다.** 이 값은 훅이 본 Win 누름에서 참이 되고 뗌에서 거짓이 됩니다. 어떤 이유로든 뗌을 놓치면 참으로 굳습니다.

굳은 뒤에는 **사용자가 누르는 모든 키가 이 갈래로 들어와 Win 누름을 주입받습니다.** `Alt+V`를 누르면 시스템은 `Win+Alt+V`를 보게 됩니다. 어떤 조합키도 원래 뜻대로 동작하지 않습니다.

사용자가 "터미널에서 Ctrl+V는 되는데 Claude Code CLI에서 Alt+V가 안 된다"고 보고했습니다. **이 갈래가 원인인지는 확정되지 않았습니다.** 다만 이 코드는 원인 여부와 무관하게 그 자체로 결함이고, 이 프로젝트에서 같은 실수를 이미 두 번 고쳤습니다.

- `FIX-PEEK-CTRL-STALE.md`: `peek_ctrl_`이라는 기억이 낡아 화면이 번쩍였습니다.
- `FIX-CORNER-DRAG-CTRL.md`: 훅이 본 Ctrl 뗌 사건에 감시 종료가 매여 드래그 중에 실패했습니다.

**둘 다 `GetAsyncKeyState`로 실제 키 상태를 읽어 해결했습니다. 세 번째도 같습니다.**

---

## 2. 고칠 것

### 2-1. 갈래에 들어가기 전에 실제 키 상태로 검증한다

`g_win_held`를 조건에 쓰기 직전에 실제 키가 눌려 있는지 확인하십시오. 어긋나 있으면 기억을 바로잡고 그 갈래로 들어가지 않습니다.

```cpp
  if (g_win_held) {
    const bool win_really_down = (GetAsyncKeyState(VK_LWIN) & 0x8000) != 0 ||
                                 (GetAsyncKeyState(VK_RWIN) & 0x8000) != 0;
    if (!win_really_down) {
      g_win_held = false;
      g_win_combo = false;
      g_win_injected = false;
    }
  }
```

이 검사를 `const bool is_win = ...` 바로 앞에 두십시오. **`is_win` 갈래보다 앞이어야** 굳은 상태가 그 아래의 모든 판단에 섞이지 않습니다.

`GetAsyncKeyState`는 값싼 호출이지만 훅은 모든 키를 탑니다. **`g_win_held`가 참일 때만 부르도록** 위 형태를 지키십시오. 평소에는 한 번도 불리지 않습니다.

### 2-2. 훅 안에서 로그를 부르지 않는다

`FIX-HOOK-LOG-FLOOD.md`에서 확인한 대로, 저수준 키보드 훅은 상단바의 UI 스레드에서 돌고 `Log`는 전역 뮤텍스와 파일 쓰기를 합니다. **이 함수 안에 어떤 로그도 넣지 마십시오.**

어긋남을 발견했다는 사실을 남기고 싶으면 `PostMessageW`로 창에 알리고 창 절차에서 남기십시오. 다만 **이번에는 그것도 하지 마십시오.** 어긋남이 드물다면 로그가 없어도 되고, 잦다면 다른 증상으로 먼저 드러납니다.

---

## 3. 하지 말 것

- `Alt`나 `V`를 훅에서 가로채는 코드를 넣지 마십시오. 지금 코드는 `Alt`도 `V`도 삼키지 않습니다. 그대로 두십시오.
- Win 키 처리의 의도를 바꾸지 마십시오. Win 단독 누름으로 시작 메뉴를 열고 Win+Space로 Spotlight를 여는 동작은 그대로여야 합니다.
- `Ctrl`을 삼키지 마십시오. 반드시 `CallNextHookEx`의 반환값으로 빠져나가야 합니다.

---

## 4. 검증

1. Release 클린 빌드가 경고 없이 통과해야 합니다.
2. **Ctrl+C와 Ctrl+V**가 그대로여야 합니다.
3. **Win 단독 누름**으로 시작 메뉴가 열려야 합니다.
4. **Win+Space**로 Spotlight가 열려야 합니다.
5. **Win+E, Win+R 같은 조합키**가 그대로 동작해야 합니다. 이 항목이 2-1의 회귀를 잡습니다.
6. `LowLevelKeyboardProc` 안에 `Log` 호출이 없어야 합니다. 코드로 확인하십시오.

이 환경에서는 마우스와 키보드 입력을 합성할 수 없습니다. **사용자 화면에 입력을 밀어 넣으려고 하지 마십시오.** 3~5번은 코드 경로를 설명하고 사용자 확인으로 넘기십시오.
