# 작업 지시서 3: 유휴 상태에서 UI 스레드가 포화되는 문제

> 작업 당시의 진단과 지시를 남긴 기록입니다. 현재 코드의 설명이 아닙니다.

커밋 `66b3527`로 메뉴 클릭과 호버는 동작하게 되었습니다. 그러나 메뉴를 네 번쯤 열고 나면 여전히 멈춥니다.

이 문서는 그 멈춤의 유력한 원인인 **UI 스레드 포화**를 다룹니다. 부수적으로 팝업 배치 결함 하나와, 멈춤이 재발할 경우를 대비한 계측을 함께 지정합니다.

---

## 0. 해결된 것

`66b3527` 이후 처음으로 메뉴 명령이 실행되었습니다.

```
09:00:25.751 [popup] open rows=7 shown 16ms
09:00:27.141 [popup] msg=lbuttondown pt=77,140 inside=1
09:00:27.220 [popup] msg=lbuttonup pt=77,140 inside=1
09:00:27.220 [popup] dismiss reason=invoke index=4
09:00:27.223 [dock] menu cmd=4 show-all name=explorer.exe windows=1
```

여기서 중요한 사실이 하나 확인되었습니다. **팝업은 마우스 메시지를 정상으로 받습니다.** `msg=lbuttondown ... inside=1`이 그 증거입니다.

즉 `FIX-POPUP-2.md` 1장에서 "배경 창이라 안쪽 클릭 메시지가 도달하지 않는다"고 적었던 진단은 **틀렸습니다.** 메시지는 도달하고 있었고, 실제 실행 경로도 폴링(`poll invoke`)이 아니라 메시지(`msg=lbuttonup`)였습니다.

다만 폴링 구현은 그대로 두십시오. 메시지가 유실되는 상황의 보조 경로로 유효하고, 호버 갱신에도 쓰이고 있습니다. **되돌리지 마십시오.**

표시 지연도 계속 목표를 만족합니다. `shown` 값이 16ms, 15ms, 0ms, 0ms입니다.

---

## 1. 남은 문제와 증거

### 1.1 유휴 상태에서 UI 스레드가 포화된다

앞선 측정값입니다.

- 유휴 60초 동안 누적 CPU **47.9초**. 목표는 1초 미만입니다.
- UI 스레드가 거의 전부를 차지합니다. `PipeServer` 스레드가 아닙니다.

방금 재현한 로그에도 같은 패턴이 남아 있습니다.

```
09:00:21.992 [perf] rebuild items=12 pins=12 shown=0 468ms
09:00:22.798 [perf] rebuild skip items=12 31ms
09:00:31.902 [perf] rebuild skip items=12 16ms
```

`shown=0`에 주목하십시오. **독이 화면에 보이지도 않는 상태에서** 목록을 다시 만들고 있습니다.

### 1.2 이것이 멈춤의 유력한 원인이다

UI 스레드가 이미 80% 가까이 포화된 상태에서, 팝업이 50ms 주기로 폴링하며 호버가 바뀔 때마다 `UpdateWindow()`로 동기 렌더를 겁니다. 메뉴를 여닫을 때마다 부하가 누적되고, 네 번째쯤에서 스레드가 넘어갑니다.

사용자가 겪은 "두 번째부터", "네 번째쯤에서" 같은 들쭉날쭉한 횟수는 고정된 논리 오류가 아니라 **부하 임계점**의 특징입니다.

따라서 멈춤을 더 파기 전에 **이 포화부터 없애야 합니다.** 원인을 하나 제거한 뒤 재현해야 남은 문제가 보입니다.

### 1.3 근본 원인

경로는 다음과 같습니다.

```
Dock::WinEventProc → kTasksChangedMsg → ScheduleRebuild → Rebuild → CollectDockApps
```

문제는 두 가지입니다.

1. **독이 숨겨져 있어도 목록을 다시 만듭니다.** 화면에 없는 것을 위해 계산합니다.
2. **비교가 수집 뒤에 있습니다.** `PLAN.md` 4-4의 "결과가 같으면 건너뛴다"는 `CollectDockApps()`를 전부 실행한 **다음**에 이전 결과와 비교합니다. 그래서 `skip`으로 판정돼도 31~62ms는 이미 써 버린 뒤입니다. 로그의 `rebuild skip ... 31ms`가 정확히 그 상태입니다.

## 2. 수정 지시

### 2-1. 독이 숨겨져 있으면 목록을 만들지 않는다 (필수, 최우선)

이 항목 하나로 유휴 CPU가 거의 0에 수렴해야 합니다. 독은 대부분의 시간 동안 숨겨져 있기 때문입니다.

`src/dock.cpp`의 `ScheduleRebuild()`와 `Rebuild()`를 다음 규칙으로 바꾸십시오.

- `shown_`이 거짓이면 `pending_rebuild_ = true`만 세우고 **즉시 반환합니다.** 타이머도 걸지 않습니다.
- `ShowPill()`에서 독을 보이기 직전에 `pending_rebuild_`가 참이면 그때 한 번 `Rebuild()`를 수행합니다.
- 이미 있는 `Busy()` 가드는 그대로 둡니다.

독이 보이는 동안에는 지금처럼 디바운스 타이머로 갱신합니다. 사용자가 독을 보고 있을 때만 최신 상태가 필요하기 때문입니다.

`ShowPill()`에서 `Rebuild()`를 부르면 독이 나타나는 순간에 지연이 생길 수 있습니다. 2-2가 그 비용을 줄여 주므로 함께 적용하십시오.

### 2-2. 비싼 수집 전에 싼 지문으로 먼저 거른다 (필수)

`Rebuild()`가 실제로 필요한지를 **`CollectDockApps()`를 부르기 전에** 판정하십시오.

`src/task_list.cpp`에 가벼운 지문 함수를 추가합니다.

```cpp
// 창 목록이 바뀌었는지만 판정한다. 프로퍼티 스토어와 제목을 읽지 않는다.
uint64_t TaskWindowFingerprint();
```

구현 지침입니다.

- `EnumWindows`로 순회하되, 각 창에 대해 `IsTaskWindow()` 판정까지만 합니다.
- 통과한 창의 `HWND` 값을 순서대로 섞어 64비트 값 하나로 만듭니다. 개수도 함께 반영하십시오.
- **프로퍼티 스토어 조회, 제목 읽기, 아이콘 추출을 하지 마십시오.** 이 셋이 비용의 대부분입니다.

`Dock::Rebuild()` 첫머리에서 이 지문을 이전 값과 비교하고, 같으면 `CollectDockApps()`를 부르지 않고 즉시 반환하십시오. 지문 계산 자체가 목표 **2ms 이하**여야 합니다. 넘으면 `IsTaskWindow()` 안에서 비싼 호출을 하고 있다는 뜻이므로 그 지점을 찾아 보고하십시오.

핀 목록이 바뀌었을 때는 지문이 같아도 갱신이 필요합니다. `ApplyMenuCommand()`의 고정·고정 해제 경로에서는 지문 검사를 건너뛰도록 별도 플래그를 두십시오.

### 2-3. WinEvent 콜백에서 관심 없는 창을 먼저 버린다 (필수)

`Dock::WinEventProc`는 현재 최상위 창의 이벤트를 모두 게시합니다. 콜백에서 값싼 검사로 더 걸러내십시오.

```cpp
if (!IsWindowVisible(hwnd) && event != EVENT_OBJECT_DESTROY && event != EVENT_OBJECT_HIDE) {
  return;
}
if ((GetWindowLongW(hwnd, GWL_EXSTYLE) & WS_EX_TOOLWINDOW) != 0) {
  return;
}
```

콜백은 시스템 전역 경로이므로 **여기서 비싼 호출을 하지 마십시오.** COM, 프로퍼티 스토어, `SendMessage`, 파일 입출력을 넣으면 안 됩니다. 위 두 검사 이상으로 늘리지 마십시오.

### 2-4. 디바운스를 늘린다 (필수)

`kRebuildDelayMs`를 150에서 **300**으로 올리고, **후행 디바운스**로 바꾸십시오. 즉 새 이벤트가 올 때마다 타이머를 다시 걸어, 이벤트가 멎은 뒤 300ms에 한 번만 수행되게 합니다.

현재는 타이머가 이미 걸려 있으면 그대로 두는 구조일 수 있습니다. `SetTimer`를 같은 ID로 다시 호출하면 시간이 초기화되므로, 조건 없이 다시 거는 것으로 충분합니다.

### 2-5. 팝업이 커서 경계에 걸리지 않게 한다 (필수)

로그에서 다음이 확인됩니다.

```
09:00:31.137 [popup] msg=mousemove pt=-3,218 inside=0
09:00:32.466 [popup] msg=mousemove pt=0,252 inside=0
```

메뉴가 열린 **직후에 커서가 팝업 바깥으로 판정됩니다.** 원인은 `PopupSurface::Place()`입니다.

```cpp
int x = anchor_screen.x;
int y = mode == Anchor::AboveAt ? anchor_screen.y - size.cy : anchor_screen.y;
```

`AboveAt`에서 팝업의 아래 모서리가 커서 좌표와 정확히 겹치고, 왼쪽 모서리도 커서 x와 겹칩니다. `PtInRect`는 오른쪽과 아래 경계를 포함하지 않으므로, 커서는 **항상 바깥으로 판정됩니다.**

이 상태에서는 커서가 조금만 흔들려도 안팎 판정이 뒤집히고, 가드 타이머의 `outside-poll`이 사용자가 의도하지 않은 시점에 메뉴를 닫을 수 있습니다.

다음과 같이 고치십시오.

- `AboveAt`에서 팝업과 커서 사이에 DPI 기준 **4dip 간격**을 둡니다. 즉 `y = anchor.y - size.cy - Dip(4)`로 띄웁니다.
- 가로는 커서를 기준으로 **살짝 왼쪽으로 당겨** 커서가 팝업 가로 범위 안쪽에 오게 합니다. 독 아이콘 위에서 열리므로, 아이콘 중앙 정렬이 자연스럽습니다. 다만 이번에는 범위를 넓히지 말고, `x = anchor.x - Dip(8)`처럼 최소한만 조정하십시오. 화면 경계 보정은 지금 로직을 그대로 유지합니다.
- `BelowAt`도 같은 방식으로 아래로 4dip 띄웁니다.

간격을 두면 커서가 팝업 밖에 있는 것이 **명확해집니다.** 경계에 걸쳐 판정이 흔들리는 것보다 낫습니다. 사용자는 메뉴 쪽으로 커서를 움직여 들어가면 됩니다.

### 2-6. UI 스레드 정지를 계측한다 (필수)

2-1부터 2-5까지 적용해도 멈춤이 남을 수 있습니다. 그때 원인을 지목할 수 있도록 심장박동 로그를 남기십시오.

`PopupSurface::OnGuardTimer()` 안에 틱 카운터를 두고, **20틱(약 1초)마다 한 줄**만 기록합니다.

```cpp
Log(L"popup", L"alive tick=%u hot=%d inside=%d", tick_, hot_, inside ? 1 : 0);
```

매 틱마다 기록하면 로그가 넘치므로 반드시 20틱마다 남기십시오.

이 줄이 있으면 다음 재현에서 로그가 끊긴 시점이 곧 UI 스레드가 멈춘 시점입니다. 마지막 `alive` 줄과 그 직전 줄이 범인을 가리킵니다.

## 3. 하지 말아야 할 것

- `UpdateWindow()` 관련 수정과 폴링 입력 처리를 되돌리지 마십시오. 0장의 로그가 둘 다 작동함을 보여 줍니다.
- `Open()`에 `target_.Reset()`을 다시 넣지 마십시오.
- `WH_MOUSE_LL`이나 `WH_KEYBOARD_LL`을 도입하지 마십시오.
- `SetForegroundWindow`와 `AttachThreadInput`을 도입하지 마십시오.
- `WS_EX_NOACTIVATE`를 떼지 마십시오.
- WinEvent 콜백에 2-3에 적은 두 검사 이상을 넣지 마십시오. 이 콜백은 시스템 전역 입력 경로입니다.
- 아이콘 추출을 워커 스레드로 옮기지 마십시오. `PLAN.md` 5단계의 판단대로, 측정으로 병목이 확인되기 전에는 하지 않습니다.
- `spotlight.cpp`와 `spotlight.hpp`의 미커밋 수정을 건드리지 마십시오.

## 4. 검증

**CPU (핵심)**
- [ ] 프로그램을 띄우고 아무 조작 없이 60초 둔 뒤, 누적 CPU가 **1초 미만**이다. 측정 방법은 다음과 같다.

  ```powershell
  $p = Get-Process bamti; Start-Sleep 60; $p.Refresh(); $p.CPU
  ```
- [ ] 유휴 60초 동안 `[perf] rebuild` 줄이 **한 줄도** 남지 않는다.
- [ ] 지문 계산이 2ms 이하다. 넘으면 수치를 보고한다.

**독 동작 (회귀)**
- [ ] 독을 숨겼다가 다시 꺼내면 실행 중인 앱 목록이 최신이다.
- [ ] 앱을 새로 실행한 뒤 독을 꺼내면 그 앱이 보인다.
- [ ] 앱을 종료한 뒤 독을 꺼내면 그 앱이 사라진다.
- [ ] 독이 나타날 때 눈에 띄는 지연이 없다.
- [ ] 고정과 고정 해제가 즉시 반영된다. 2-2의 지문 우회가 여기서 확인된다.

**메뉴**
- [ ] 메뉴를 **열 번 연속** 열고 닫아도 멈추지 않는다. 이번 재현은 네 번째에서 멈췄으므로 열 번을 기준으로 한다.
- [ ] 메뉴가 열린 직후 커서를 그대로 두어도 저절로 닫히지 않는다. 2-5가 여기서 확인된다.
- [ ] 항목 클릭이 실행되고 `[dock] menu cmd=`가 남는다.
- [ ] 멈추면 마지막 `[popup] alive tick=` 줄의 시각과 그 다음 줄을 보고한다.

**표시 (회귀)**
- [ ] `[popup] open ... shown` 값이 16ms 이하를 유지한다.

**빌드**
- [ ] Release 빌드가 `/W4` 경고 없이 통과한다.
